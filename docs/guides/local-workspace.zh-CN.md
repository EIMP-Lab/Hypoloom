# 整理本地工作目录

[English](local-workspace.md) · 简体中文

`.local/` 是被 Git 忽略的本机工作目录，可能同时包含多个版本积累的开发证据、
私有 Issue 报告、构建环境和服务状态。当前实现由 Git 跟踪的源码、运行指令及
Profile 模板定义，不能把 `.local/` 的全部内容视为当前版本。个人 Profile
另存于 `profiles/local/`，科研运行状态通常位于 `state/`。

本指南提供一种整理已有开发工作区的方法。新克隆不包含这些私人文件，也不需要
为运行 Hypoloom 强制创建下述目录。提交说明文档即可，本地证据和数据不入库。

## 当前证据与开发历史

保留原始证据路径，增加简单的浏览目录：

```text
.local/
  README.md / README.zh-CN.md
  current/
    README.md / README.zh-CN.md
    qualification -> ../qualification/<综合验收目录>
  history/
    README.md / README.zh-CN.md
    qualification/        # 指向以往验证阶段的链接
    analysis/             # 指向保留的诊断材料
    reviews/              # 指向审查材料
    ui-reviews/
    run-reviews/
    worktrees/
    audit/
    split/
    builds/               # 指向保留的构建、安装目录
    notes/                # 实际移入无引用的个人草稿
  qualification/          # 原始证据仍在此处
  analysis/               # 原始诊断仍在此处
  ...                     # 已有私人数据与运行服务目录
```

`current/` 和 `history/` 中的材料入口使用相对符号链接；分类目录、说明文档及
明确归档的松散笔记是普通目录或文件。链接浏览的是同一份原件，不复制证据。
已有引用继续使用原路径。这些链接
仅用于浏览：**不要把它们作为运行或状态根目录、源码工作区、解释器前缀传入命令**。

`current/qualification` 指向为当前已提交运行时代码基线选定的综合验收材料。
本地 README 说明对应的 Git 提交、原始证据路径、验证范围与局限。例如，
9 月 26 日综合提交的证据仍保存在
`.local/qualification/dev-submit-20260926/`。

`current` 这个名称不会自动证明证据适用于未来的 HEAD 或未提交修改。判断依据
仍是 Git 和已有的[资格记录](../qualification.zh-CN.md)，浏览目录不增加版本
清单或验证门控。代码修改后，应根据已有验证结果更新本地说明及选定的链接。
不能按目录日期推断版本，也不能通过重命名旧证据暗示它验证了新提交。版本不明的
材料先列入历史目录，明确说明“待判定”，待查清后再分类。

开发历史也包括当前实现中仍存在的功能的早期阶段，不表示这些功能已被移除、
对应验证已通过或材料可以删除。原始失败与后续通过的检查应始终能分别辨认。

## 哪些材料保留原位

| 材料 | 保留原路径的原因 |
| --- | --- |
| 运行状态、会话、运行时 bundle 及对应证据 | 已记录的绝对路径、规范路径检查和原始引用可能依赖此位置；迁移实体后在旧址留下兼容链接，仍可能破坏这些条件。 |
| Git worktree | Git 记录了工作树位置。通过历史入口浏览即可；后续迁移或移除需使用 Git，并单独核对未合并工作。 |
| Python/Conda 及已安装包的环境 | 解释器前缀、安装脚本和记录的运行输入可能包含绝对路径。 |
| `gpu-pools/` | 可能包含活动服务的 socket 及持久资源状态。仅看到文件不能判断服务是否存活。 |
| `credentials/` | 即使个人 Profile 已采用内联凭据，保留的旧运行仍可能引用旧凭据文件。 |
| `claude/` | 可能是本项目 Claude Code 会话存储链接的持续写入目标，不能一概视为测试缓存。 |
| `issue-reports/` | 提交的原始报告、工作副本与分析材料保留现有私有布局，遵守约定的保留及披露范围。 |

文档引用的原始分析、审计和验证文件同样保留原位。只有确认记录的路径和进行中的
工作都不依赖原文件名后，才实际归档松散的个人草稿。其他历史材料留在原位置，
通过历史目录的链接收录。

涉及真实运行状态时，应分别检查持久记录与进程、服务是否存活。整理文件不构成
启动、恢复、迁移、结算或删除科研运行的授权，也不改变当前控制环境，不会用
历史环境替换运行所记录的运行时。

## 后续如何维护

1. 新证据继续写入已有的规范分类路径，例如 `.local/qualification/<任务>/`
   或 `.local/analysis/<任务>/`，不要经 `current/` 或 `history/` 写入。
   科研运行和服务的路径保持不变。
2. 按现有资格流程验证，保留包括失败在内的原始结果。原生 Unix socket 需要
   短路径时，使用较短的一次性测试根，并在证据中记录实际位置；不要通过浏览目录
   加深 socket 路径。
3. 结果明确后，更新本地双语说明和浏览链接。为当前基线选定综合验收证据，
   早期阶段继续从历史目录访问。仅修改文档的提交本身不会产生新的运行时验证，
   应准确说明沿用的代码基线。
4. 删除候选另行审查，先核对引用、保留证据、工作树修改和真实进程归属。
   目录较旧，或没有明显的前台进程，都不足以证明可以删除。本布局不引入自动清理。

所有私有内容和浏览链接都继续受已有 `.local/` Git 忽略规则保护。链接不会使其
目标自动脱敏。不要把整个工作区、私人索引或个人数据作为 Issue 附件；遵循
[Issue 报告说明](../../CONTRIBUTING.zh-CN.md#报告-issue)，分享前检查实际导出包。
凭据位置及模型认证见[个人配置入口](../../config/README.zh-CN.md)。
