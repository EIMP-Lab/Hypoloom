# 阅读助手与并行假设论证

[English](reading-and-proposals.md) · 简体中文

论文索引会列出检索候选的 URL、首批全文状态及观察到的机构策略。这些条目是元数据，
不是已接纳的阅读来源。围绕明确的证据问题选文献；现有文档工具每次最多处理两个来源，
在既有期限内完成公开、开放获取及机构通道的尝试。首批 PDF 缺失不代表最终不可获取。
年代分层不代表科学相关性排序：方法、假设或评估证据有缺口时，使用针对性的学术补充
检索。保留实际来源、版本和页码引用，区分获取方式、全文可用与实际阅读。

新建的 ACI-26 运行允许同一专家的 FORWARD 与 BACKWARD 同时执行。
Host 先记录 FORWARD 请求，使两侧复用同一组已接纳的 Leader 建议；随后在普通
Agent 容量和预算允许时启动 BACKWARD。SYNTHESIS 必须等待两侧结果正式接纳。
只有一个可用名额时自然串行。既有运行保持原固定 bundle，不支持跨版本迁移。

两侧是各有独立会话与工作目录的固定任务，不代表已经生成两条假设。
综合阶段可以提出一条或多条可独立检验的机制。证据有限、实验有先后依赖、
或者差异只是普通超参数变化时，选择单条候选仍然合理；在候选已有的 `claim` 或
`assumptions` 中说明理由，不另加输出字段。

新请求还会收到简明的 `exploration_progress`：已接受批次及假设总数、最近三个
批次的实际宽度，以及当前 OPEN 任务涉及的研究链数。Host 直接复用已接受的批次
历史和 Attempt 记录；这是请求生成时的观察，不是实时 GPU 利用率或待执行队列。
两侧论证和综合阶段会主动寻找获准上限内的独立机制；“每条链一个机制”不等于
“每位专家只留一条链”。独立链可交错准备和执行实验，未用满宽度时说明科学理由，
不为凑数生成候选。管理器先比较实际宽度与配置上限，再决定是否调整容量，并把
能够排除解释的有效负结果视为已验证探索。

| 设置 | 含义 |
| --- | --- |
| `max_hypotheses_per_round` | 每位专家每轮候选数的配置上限 |
| 实际请求中的 `effective_max_forks` | 本次提案获准使用的候选上限 |
| `max_forks` | 专家活跃研究链的并发上限 |
| `max_active_agents` | 包括论证任务、阅读助手的共享 Agent 容量 |

一侧失败重试时保留已成功的另一侧；必需的一侧最终失败后，Host 取消并排空
仍在运行的另一侧，不伪造科学否定。停止、API 恢复和计费沿用已有机制。

## 并发占用与实验等待

Web 分别显示 Agent、实验、评审占用，以及每位专家的活跃假设链和链上限。
占用来自持久化 OPEN Attempt，不代表进程心跳；旧运行缺失的限额保持未知。
链额度已满本身不代表还有候选就绪或正在等待。

执行 Agent 通常把已提交实验交给 Host，结束本次调用并释放 Agent 名额。
实验继续占用 Process 和假设链容量。Web 区分“已有交接记录的待完成实验”和
“仍占名额的执行会话”，显示后者最早提交后经过的时间。这不是空闲时间测量：
会话可能仍在检查或修复工作。

新 Host 提供上一轮调度实际考虑过的 Agent 任务及未启动原因：额度、同链工作、
实验完成、工作目录／文献准备、恢复或暂停。Web 仅在 Host 联系新鲜且调度观测
不超过 30 秒时显示这些原因；API 排队和资源等待沿用各自的实时观测。旧 Host
未提供派发详情时，不推断为“没有就绪任务”；失联时明确标记为上次观测。

每轮批量调度先派发结果分析和裁决，再派发新的设计／提案；每个优先组内按专家
轮转，每位专家获得一次机会后才分配第二次。保留原组件轮转和更早的执行结果
收集恢复。所有任务仍经过原有并发、依赖、预算、暂停和时限检查，不预留空闲槽，
不新增持久队列或提前生成候选。Host 调度改动用于新运行；重新打开 Web 观察器
可更新保留运行的只读展示，不替换其冻结 Host。

## 准备文献并委派阅读

需要时在 Profile 的文献工具列表中启用 `read_papers`。阅读助手需要父 Attempt
已经接纳的文献来源。已有来源见 `/papers/INDEX.md`；新文献使用现有 document 工具：

```text
web_fetch(mode="document", url="https://example.org/paper")
  -> status="available", source_ref=...
read_papers(action="submit", readings=[{
  "reading_id": "method-check",
  "paper_ref": <返回的 source_ref>,
  "question": "文中报告的机制依赖哪些假设？"
}])
read_papers(action="wait", max_wait_seconds=10)
```

将 `source_ref` 原样填入 `paper_ref`。URL、DOI 不等于已接纳引用；工具不会
猜测文献或为错误引用隐式下载。submit 只接受 `action` 与 `readings`，查询、
等待和取消使用独立的 status、wait、cancel 调用。未知参数会提示字段名，不回显值。
根据反馈修正后再次提交。批量中任意一项无效时不创建任何阅读任务；相同 ID 和问题
的重复提交复用原命令，冲突复用仍报错。

阅读助手消耗普通 Agent 和费用预算，由父专家核查证据并综合结论。若没有助手能够
启动且 wait 提示容量或预算不足，可以取消未启动问题后自行阅读原文，或者说明限制。
不支持阅读助手递归委派。

## 理解专家卡片

文献准备发生在综述模型启动之前。如果某篇文献的落地页或目录地址解析为非公网地址，
该篇保留为仅有书目信息的 `PDF_UNAVAILABLE`，不产生全文证据主张；Host 继续交付其他
有效文献，避免整批重复抓取。地址、重定向和实际连接地址检查保持严格，被拒绝的条目
不能通过缓存 PDF 或后备检索绕过检查。该规则同时适用于初始 Grounding 与后续专家文献
综述。检索覆盖校验及覆盖不足的反馈保持不变；未分类的适配器错误仍正常上报。

现有下载历史记录文献身份、被拒绝的地址字段、域名和校验代码，不记录 URL 路径、
凭据或解析出的地址。Web 对已有地址拒绝记录的域名隐藏外链，原始元数据仍可查看。
后续独立请求会重新检查地址。

**Automatic recovery ended** 表示该节点已记录最终失败，不会继续自动重试。专家卡片
显示失败阶段与尝试次数；**Expert details → Failure details** 可查看具体诊断，即使
失败发生在模型会话启动之前。TUI 同样显示自动恢复结束状态。重新打开监控可将这些
展示改进用于保留运行；检索行为修复用于新运行，切换 API、刷新 Web 或更新代码目录
不会重新打开已最终失败的节点，也不会替换现有运行的冻结代码。

概览卡片显示当前工作、Agent 活动、token 用量与运行提醒。点击 **Expert details**
查看活跃研究链与上限、本轮已接纳候选、FORWARD/BACKWARD/SYNTHESIS 状态、
阅读任务和记录覆盖情况。详情跟随所选专家，随观测轮询更新；其中的
**Browse expert history** 可进入该专家的会话与工具历史。
阅读任务按已接纳 command ID 计数；重试增加 Attempt 数，不增加任务数。
被拒绝的阅读调用不算助手，也不虚构子 Agent 费用；实际调用和失败重试仍进入原有
Token 与费用汇总。

Web 与 TUI 使用独立 **Grounding Agent** 卡片显示检索规划、Grounding 及其委托的
阅读助手，完成后保留状态、Token 用量、任务跨度、阅读助手数量和共享证据；Web 任务
详情可折叠。**Global tasks** 显示其余全局工作：Observer、图进化、最终报告和
独立辩论裁决。即使记录的执行角色属于某位专家，它们也服务于
整个运行。专家卡片及其会话筛选只包含专家所属工作；阅读助手跟随已有父任务委托。
历史归属不明时明确显示未知。Attempt 详情分别显示任务归属、执行角色与实际模型。

**Details & history** 使用已有抽屉查看全局用量、恢复和历史。Grounding 共享状态
区分准备中、等待澄清和已接纳；只有实际科研请求包含该接纳结果引用，才显示已提供给
对应专家。提供输入不代表模型已阅读或理解。已完成的全局工作保持紧凑，专家筛选不
隐藏全局概览。TUI **d** 查看执行详情，**w** 打开完整 Web 历史与共享详情。

Host 支持且观测新鲜时，卡片还显示实时 RPM。Web 子灯按自身 Attempt RPM，专家／
Grounding 主灯按汇总 RPM，同等 RPM 下主灯稍慢；未知、失联或零 RPM 停止动画，
Process 灯保持静态。详见[请求限速与 RPM](provider-recovery.zh-CN.md#本运行的-rpm-与并发控制)。

Token 与重试观测分为全局、专家和归属未知三部分，每个 Attempt 沿用现有统计，只
计算一次。运行总量与预算控制不变。重新打开使用新版代码的监控即可用于已有运行，
无需重启或迁移研究 Host，也不修改冻结代码。

工具观测来自当前调用捕获的 tool_use/tool_result，以已有事件 ID 去重。
记录缺失或不完整时显示下界和未知覆盖，不将缺失当作零错误。历史等待原因可能已经
变化；缺少原因时不能断言具体阻塞位置。OPEN 表示持久化执行状态，不等于进程心跳。
CLI 与支持报告使用相同的只读汇总。

本改动不保证固定倍数加速或科研质量提升。实际验证范围和限制见
[qualification](../qualification.zh-CN.md)。
