# 代码实现检验

[English](implementation-verification.md) · 简体中文

专家提交实际捕获的代码后，Host 自动发起独立检验，检查正确性、工程合理性和计算效率。
检验者不提出假设，也不判断研究价值或科学结论。检查内容从当前实现产生，不需要预设
研究方向、算法名称、基准等价关系或统一的向量化指标。

在 `/autoresearch init` 中指定检验者的准确模型 ID，可独立选择比研究专家更强的模型。
沿用基模也需要明确选择，不会静默回退。可选 effort 为 `low`、`medium`、`high`、
`xhigh`、`max`。也可在 `experts.yaml` 中与 `grounding` 并列设置 `verifier.model`
和 `verifier.effort`，或向 bootstrap / `hypoloom.cli start` 传入
`--verifier-model MODEL_ID --verifier-effort high`。启动参数在内存覆盖 Profile，经同一
编译器验证后写入运行配置，不改写私有 Profile；预览显示最终模型与来源。
检验者不是 `experts[]` 成员，不继承作者的模型覆盖或私人记忆。

首次检查给出有来源的问题及小型 Python 探针。Host 在现有沙箱内使用授权资源执行，
候选代码与目标目录只读，最多 120 秒。探针释放资源后，由独立会话复核实际证据，之后
才允许正式计算。探针有独立执行记录，不成为科研结果，也不占用正式计算的重试序号。
代码问题和证据不足分别记录，经已有工程修复流程反馈。等待时作者使用 execution
handoff 释放 Agent 容量。同一运行的相同捕获内容可复用近期证据；代码、入口、环境
或资源配置变化重新检验。小型探针不能证明全部代码正确。

新探针自行声明检查内容，使用 Host 提供的通用断言和计时辅助库，记录实际断言、失败、
异常和未执行项；打印 PASS 或退出码为 0 都不足以通过。复审会话同时读取探针源码和
实际结果，明确已测条件、未测条件和阻断性缺口。测量只说明所测负载的实际耗时。
报告格式错误在原调用和原预算内纠正，使用 `methodology.yaml.output_correction`；
模板在第三次失败校验后结束纠错机会。系统不会自动增加一轮探针修订。

TUI 和 Web 在 Grounding 旁显示**代码实现检验者**卡片，逐专家展示交付、检验触发、复用、
已完成的首次通过率、阻断问题和建议。报告生成、交付到专家任务输入、专家回复、提交修复、
独立复核解决分别记录；已交付不表示读懂或修好。问题通过报告主键及问题 ID 定位，解决
必须引用原问题并给出新证据。检验费用只计入全局账目，作者归属展示不会重复收费。
TUI 按 **v**、Web 点击**检验历史**查看分页报告。Host 观察过期时保留未确认标记，
旧运行显示不支持。

卡片还展示阶段耗时、报告纠错、逐项检查、覆盖范围以及可观察的实际请求与响应模型，
将验证未完成、调用故障和专家代码缺陷分开统计。未发送 thinking 参数不代表供应商已
关闭推理。交付证据只读取有界近期窗口；更早记录无法确认时明确标为观察不完整，
不据此判定尚未交付。累计交付数及首次通过率仍从完整检验历史计算。

机制用于新建运行，不热升级或迁移既有冻结运行。
