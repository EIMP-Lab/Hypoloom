# 代码实现检验

[English](implementation-verification.md) · 简体中文

## 查看验证证据和修复实验

从 ACI 48 起，检验者从验证输入的 `start_here` 页开始。初检显示候选文件或本次修复的差异、实际命令、项目要求和未解决的问题。复核按检查列出预期依据和实测结果，缺失的观测也会显示。输入索引提供完整源码、探针和日志。需要旧报告时，检验者可以用 `read_verification_report` 按页读取本次目录中列出的原文。同一交付链上未解决的问题会一直保留，即使报告已早于最近 16 份。

执行专家可用 `{"candidate_ref":"design"}` 提交已接受的设计。修复时，将前次实验 ID 同时填入 `candidate_ref` 和 `replaces_experiment_id`，再提交有变化的候选字段。Host 捕获当前实现，并可从原件继承本地缺失的评分文件和样例。修改已冻结的解析器需要重新声明科学口径。回执中的 `resource_estimate_ref` 可以复用相同工作负载的资源估计。Host 为新提交分配资源时会纳入该负载的最新实测记录。响应丢失后，用 `get_submission_receipt` 查询首次提交或指定前次实验的回执。

设计重试会收到 Host 保存的检查点，包括通过的检查、产物摘要、失败位置和跨尝试用量。`methodology.yaml` 的 `budget.design_retry_policy` 默认为 `shadow`，记录重复的确定性失败。选用 `enforce` 后，定向修复在相同证据上再次遇到相同错误，会结束这个设计节点，并把失败检查交给该批次的上游。其他实验链可以继续。观察器运行摘要的 `research_efficiency` 按角色、阶段和请求模型汇总各次尝试记录的 Token，列出计量缺口和各评估层级每小时的可比较产出。成功和有效反证都计入。

## 项目专属工程要求

从 ACI 45 起，v4 Profile 可以在 `goal.yaml` 中给独立检验者指定工程要求。检查 ID 可用 1 至 64 个 ASCII 字母、数字、下划线或连字符。`formal_entrypoint` 由 Host 为入口样例保留。

```yaml
implementation_requirements:
  artifact_reload: 用提交的实现生成产物，通过项目公共接口重新加载，并在同一小样本上比较输出。
```

每条要求都应适用于所有提交。允许复用已有产物时，请写明如何检验复用路径。专家在运行创建时收到要求。独立检验者取得相同的 ID 和描述，为每项声明必需断言，并在评审中引用执行成功的检查。遗漏、未执行或失败的必需检查都会阻止通过。

作者提交的入口样例失败时，Host 把对应的执行证据交还作者。检验者制作的配对输入有错时，可以在同一份候选代码上修订探针。如果修订后同一检查再次出现相同的样例错误，检验者可以报告证据不足，或凭独立的候选代码证据指出实现缺陷。框架按既有修复策略处理后续正式执行。

## 独立检验流程

专家提交实际捕获的代码后，Host 自动发起独立检验，检查正确性、工程合理性和计算效率。
检验者不提出假设，也不判断研究价值或科学结论。检查内容从当前实现产生，不需要预设
研究方向、算法名称、基准等价关系或统一的向量化指标。

在 `/autoresearch init` 中指定检验者的准确模型 ID，可独立选择比研究专家更强的模型。
沿用基模也需要明确选择，不会静默回退。可选 effort 为 `low`、`medium`、`high`、
`xhigh`、`max`。也可在 `experts.yaml` 中与 `grounding` 并列设置 `verifier.model`
和 `verifier.effort`，或向 bootstrap / `hypoloom.cli start` 传入
`--verifier-model MODEL_ID --verifier-effort high`。启动参数在内存覆盖 Profile，经同一
编译器验证后写入运行配置，不改写私有 Profile；预览显示最终模型与来源。
检验者不是 `experts[]` 成员，不继承作者的模型覆盖或私人记忆。

首次检查给出有来源的问题及小型 Python 探针。Host 在现有沙箱内使用授权资源执行，
候选代码与目标目录只读，最多 120 秒。探针释放资源后，由独立会话复核实际证据，之后
才允许正式计算。探针有独立执行记录，不成为科研结果，也不占用正式计算的重试序号。
代码问题和证据不足分别记录，经已有工程修复流程反馈。等待时作者使用 execution
handoff 释放 Agent 容量。同一运行的相同捕获内容可复用近期证据；代码、入口、环境
或资源配置变化重新检验。小型探针不能证明全部代码正确。

GPU 探针有各自的资源池预留。新运行在探针关闭且确认进程组消失后释放对应预留；
停止实验或运行也会撤回尚未启动的探针排队请求。探针仍开放或进程存活情况未知时，
保留原预留。既有冻结 Host 遗留的预留需要明确限定范围的运维清理；更新源码或重启
观察界面不会清除这些记录。

新探针自行声明检查内容，使用 Host 提供的通用断言和计时辅助库，记录实际断言、失败、
异常和未执行项；打印 PASS 或退出码为 0 都不足以通过。复审会话同时读取探针源码和
实际结果，明确已测条件、未测条件和阻断性缺口。测量只说明所测负载的实际耗时。
报告格式错误在原调用和原预算内纠正，使用 `methodology.yaml.output_correction`；
模板在第三次失败校验后结束纠错机会。新运行支持有界探针修订：复审确认是探针自身
错误、且没有候选代码阻断项时，可提交修正后的探针，保留全部检查声明，由 Host 在
同一份只读候选代码上重新执行并交给独立会话复审。最多修订两次，且不超过已配置的
模型重试额度；不消耗作者的代码修复提交额度。额度耗尽仍记录验证未完成，不放行训练。
旧运行保留原冻结规则。

从 ACI 40 起，Verifier 通过 `submit_review` 直接填写判断、发现、探针、覆盖情况和证据引用。
工具按当前审查阶段给出字段，Host 填写任务类型和固定效果并校验完整回复。
ACI 39 的工具以结构化参数提交完整报告，
复用现有校验器和纠错额度，返回具体字段错误。准备成功后只需以
`{"review_submitted":true}` 结束回复，Stop 再次校验已准备的报告，之后才进入 Host 接纳。
工具成功本身不能放行训练；候选文件仍只读，探针仍单独运行。说明文字合计最多 16 KiB；
摘要、问题说明及覆盖说明单字段最多 2048 字符，检查目的和依据最多 1024 字符。
探针源码仍沿用 256 KiB 上限。旧运行保留冻结协议，更新工作目录不会改变它。

从 ACI 41 起，向 `submit_review` 提交 `probe_required` 时提供探针对象。
提交 `passed`、`changes_required` 或 `inconclusive` 时可省略该字段，Host
会补入 JSON 空值，再根据实际证据校验结论。纠错额度耗尽或校验器失效时，Host
在下一次轮询结束这次尝试并回收进程组，后续重试沿用原有预算。独立复审的证据概览
按计划列出每项检查的实际状态，缺失结果显示为空值。可通过 `probe_plan` 和报告引用
查看本次探针，也可按需展开原始观测和其他历史方案。

工程指引要求作者从实际启动入口追踪数据读取和训练调用，在已有实现说明中记录采用的
兼容优化、暂缓理由，以及有界的等价性和计时证据。新版 Verifier 通过现有探针与覆盖字段
核对实际调用和配置。读过资料或测了未被使用的辅助函数，均不能证明优化已采用。
缺少可选优化属于建议；低 GPU 利用率或局部微基准本身也不能证明整体训练性能。

ACI 37 为设计、执行和分析阶段提供更短、绑定专家插件版本的工程指引，涵盖重复数据
读取、按字节限额缓存原始特征、多进程文件句柄、保持梯度语义的损失实现和因果历史复用。
详细参考仍在同一插件内。旧插件没有简版时，只使用该插件原有的完整参考，不补入当前
种子内容。

有合理的参考实现时，检验者可声明 `comparison` 检查，调用
`hypoloom_probe.compare(id, reference, candidate, workload=..., device="cpu",
warmup=2, repeats=5)`。辅助库交替执行两种实现，记录逐次样本、中位数及其比值。
CUDA 比较必须指定 `device="cuda", synchronize=torch.cuda.synchronize`。正确性仍由
独立断言检查；测得比值小于 1 是有效观察，不自动成为科学失败。新算法不适合基线等价
检查时，应使用自身有依据的不变量。每项检查开始和结束时都会原子保存结果；进程被
终止后，未完成项仍保持未完成，不能因此放行。

真实探针成功且独立复审通过后，Host 可向同一运行、同一专家、同一组件的后续工程节点
提供只读的 `--verified-engineering-memory`。它从最近 16 次复审委托中选择最多 4 条
完整记录。ACI 38 起保存上限为 64 KiB，直接放入提示的阅读预算仍为 6 KiB，较大记录
通过分页视图读取；ACI 37 保留原来的 6 KiB 保存策略。每条绑定代码摘要、提交捕获、探针、复审、已测/未测条件
与实际测量，过大的记录整条省略；新版本即使没有记录能放入，也会报告省略数量。
独立 Oracle 会核对来源和测量值。这是按条件召回工程
证据，不是训练模型权重，也不替代新候选的检查。作者自称通过、未完成的 Process 或
未完成的复审都不能生成有效记忆。

新版本会为验证上下文、提交源码和工程记忆提供 `reading_view.index_path`。
先读索引与概览，再按需读源码、探针脚本、日志和历史报告的文本页；每页不超过
12000 字节，标明原始字段或文件名、行偏移。同一字段的页面可逐字节拼回原文。
`/inputs/NNNN.txt` 仍保存原始权威输入；分页视图沿用只读挂载和原有证据引用，
不会改写结果或放宽验证要求。

原生 CC 工程节点的每次本地 Bash 调用都在前台执行，最多 60 秒，且不超过调用剩余
时间；另保留原预算的 10%（最多 15 秒）用于交接。钩子不改写命令、不放宽原权限规则。
spawn 检查应使用有 main 保护的可导入文件，限制 join 和队列等待时间。已捕获的提交
可在作者会话超时后继续由 Host 验证；作者超时状态仍如实保留，未提交草稿不会被自动
转成正式提交。供应商 thinking 默认配置不变。

TUI 在 Grounding 旁显示 **Verifier** 摘要卡片，仅保留模型、当前阶段及逐专家
阻断/建议数；同一问题的后续报告不重复计入当前问题数。按 **v** 查看分页报告、
逐项探针检查、覆盖范围与底层调用诊断。Web 卡片逐专家展示交付、检验触发、复用、
已完成的首次通过率、阻断问题和建议。报告生成、交付到专家任务输入、专家回复、提交修复、
独立复核解决分别记录；已交付不表示读懂或修好。问题通过报告主键及问题 ID 定位，解决
必须引用原问题并给出新证据。检验费用只计入全局账目，作者归属展示不会重复收费。
Web 点击**检验历史**查看分页报告。Host 观察过期时保留未确认标记，
尚不支持检验功能的旧版本运行显示不支持。

TUI 与 Web 的卡片统一使用 **Verifier** 名称。Grounding、Verifier 和专家卡片
显示各自图标和已记录的基模名称；多个名称表示不同调用使用了不同模型，未知时显示
`—`。活动灯只在 Host 已确认、当前运行 RPM 数据新鲜时呼吸，数据过期或 Host
未确认时停止动画。呼吸频率表示请求速率，不是进程心跳。Web 尊重“减少动态效果”
偏好。这些显示更新可以只读查看兼容旧运行，不改变冻结的执行代码。

检验详情还展示阶段耗时、报告纠错、逐项检查、覆盖范围以及可观察的实际请求与响应模型，
将验证未完成、调用故障和专家代码缺陷分开统计。未发送 thinking 参数不代表供应商已
关闭推理。交付证据只读取有界近期窗口；更早记录无法确认时明确标为观察不完整，
不据此判定尚未交付。累计交付数及首次通过率仍从完整检验历史计算。

机制用于新建运行，不热升级或迁移既有冻结运行。

## 成对扰动探针

从 ACI 43 起，可以在探针检查中使用 `paired_inputs`。它只取一次样本，再比较两个副本。扰动函数原地修改其中一个副本，两个选择函数分别指出应保持不变的全部输入和必须发生变化的区域。

```python
from hypoloom_probe import check, paired_inputs

with check("prefix_invariance") as c:
    a, b = paired_inputs(draw_sample, change_suffix,
                         control=lambda row: row["prefix"], target=lambda row: row["suffix"])
    c.equal(candidate(a), candidate(b))
```

对照部分变化或目标部分没有变化时，探针记录 `ERROR`。模型输出断言失败时记录 `FAIL`。数组或张量可以提供相应的 `clone` 和返回单个布尔值的 `equal` 函数。选择函数应返回可以快照的值，例如已分离的张量。
