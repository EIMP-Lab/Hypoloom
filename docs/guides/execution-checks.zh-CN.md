# 执行前检查

[English](execution-checks.md) · 简体中文

对于必须在耗时实验之前满足的工程要求，可在 `goal.yaml` 中配置
`execution_checks`。任务提供独立于候选代码的小型检查器，每次执行（包括 LOCAL
实验和修复）都先在现有资源分配内运行检查。失败记录为 `EXECUTION_FAILURE`，
不生成科研指标，也不会算作科学否证。

| 字段 | 取值 |
| --- | --- |
| `requirements` | 1–64 个检查名称到原始要求说明的映射。名称符合 `[a-z][a-z0-9_]{0,63}`，说明非空，总计不超过 16 KiB。 |
| `argv` | 以 `python` 和一个已声明的 `.py` 文件名开头的参数列表，可附加参数，总计不超过 8 KiB。 |
| `files` | 1–64 个相对文件名到 UTF-8 源码文本的映射，总计不超过 512 KiB。文件路径不能相互包含，`context.json` 为保留名称。 |
| `timeout_seconds` | 有限正数；同时受整个实验剩余执行时间限制。 |

检查器源码随任务接纳记录固定，候选实验的补丁、启动命令和指标解析器无法替换它。
不填写此字段则保留原来的执行行为。已创建的运行继续使用原有声明和冻结运行时，
修改 Profile 不会升级已有运行。

检查器使用正式实验的 Python 运行时、只读候选文件 `/input`、打好补丁的目标代码、
读取目录及已分配设备，继承相同的环境变量（有目标仓库时包括
`HYPOLOOM_TARGET_ROOT`）。只读的 `/hypoloom-checks/context.json` 提供 `argv`
（提交的逻辑启动命令）、`input_dir`、`output_dir` 和 `requirements`。
检查器有独立的可写 `/output` 和临时 `/tmp`，工作目录为 `/output`。
正式训练另起子进程，因此探测不会消耗训练进程的随机数、采样器或优化器状态。

通过时退出码应为零，且输出目录只包含一个 `result.json`，例如：

```json
{"checks":{"actual_loss_dispatch":true,"loss_gradient_equivalence":true}}
```

检查名称必须与 `requirements` 完全一致，值必须全部为布尔 `true`。检查为假、
缺项、多项、重复 JSON 键、非布尔值、非零退出码、超时、额外输出文件或结果超过
64 KiB，都会阻止正式执行。诊断写到 stdout/stderr，临时文件放在 `/tmp`。
正常发布目录的 `raw/execution-checks/` 保存已接纳的源码、上下文、有界日志及
可用结果；驱动诊断位于原有 Process stderr。失败沿用原有的有限修复额度。

针对向量化，项目检查器应根据 `context.json.argv` 构建真实模型，实际调用损失
函数及反向传播，并覆盖可能改变分派的数据集、实验分支、精度、子类和实例覆盖。
在掩码及数值边界样本上比较损失与完整参数梯度。仅存在一个向量化函数、声明
`vectorized=true`，或只检查另一个基线模型，都不能证明要求已落实。如果构建后
仍可能改变实际分派，公共训练入口也应保留轻量断言。

前置检查应短小且有明确时间上限；完整吞吐测试另行测量。除科研协议明确冻结的
设置外，worker 数、精度等运行参数可以调整。这些检查不改变科研成功门槛。
框架负责执行任务提供的检查器，不能自动证明任意自然语言要求都已被完整转换成
可执行检查；任务编写时仍需核对覆盖范围。
