# 研究工作流与方法自进化

[English](research-workflow.md) · 简体中文

新运行会从一份公共源码，将 `research-workflow` 加入管理侧和各专家的插件。
框架使用实际绑定的插件名和当前阶段引导加载。它提供研究方法，不新增科学验收器
或权限体系。无需修改 Profile。

## 运行中的工作方式

| 阶段 | 工作方法 |
|---|---|
| Grounding | 复用已提供上下文和保留草稿，调查必要缺口，测试受托编写的验收器；仅整理背景的任务不擅自创建验收器。 |
| 文献与假设 | 根据原始来源解决未回答的问题，提出能够区分解释的实验。 |
| 实现 | 复用适用代码，保持已接纳接口，测试实际改动。 |
| 执行与修复 | 根据当前 Host 状态和原始错误，通过已有工具提交、修复和交接。 |
| 分析与报告 | 核对原始证据、对比范围及不确定性后给出结论。 |
| 自进化 | 根据观察改进具体方法，或保持不变。 |

简短入口按需指向阶段参考，不一次加载全部内容。现有文献、资源、修复、报告和交互
技能继续承担专门职责。QUERY_PLAN 和受限论文阅读助手保留精简指令。没有插件绑定的
辅助角色也保留原指令；运行时不会为加载指导而虚构绑定或额外授予插件访问权限。

初始 Grounding 只读加载管理侧插件，保留已选的执行角色、模型、effort 和预算，不能
写入 `/plugin-update`。关闭图进化时，科研节点仍使用既有专家资源。轮报资源的可用性
取决于运行版本，不是新增的用户开关。已有运行和保留的 Git 插件不会被补写。

## 科学逻辑仍由任务决定

公共 skill 不包含数据集名称、项目目录、seed 数量或固定性能门槛。分类、数值优化和
复现等任务保留自己的指标、有效性检查及解析器代码。复用实现前仍需核对其假设是否
符合当前目标。

原生 Stop hook 已执行最终 JSON 校验和隔离的解析器 smoke 测试。Agent 应使用返回的
反馈，不必再编写一套通用 schema 校验器；`/runtime/output-schema.json` 可直接读取
同一份格式要求。科学测试仍需覆盖原始数据计算、课题自身的边界、缺失证据及每项
有效性条件。针对有效性变异，直接断言对应 check 从 true 变为 false，其他检查保持
预期；仅观察总分不达标不能证明有效性检查生效。Host 已测试严格数值相等、比较
运算符及 ALL/ANY 归约，无须为重复这些框架比较反向构造复杂原始样本。smoke
通过只证明接口能工作，不代表科研目标达成。共同验收器接纳后，对专家保持只读。

当证据同时包含明细与汇总时，应从目标要求的明细、权重和样本集合独立复算；若
两种表示都必需，校验其一致性。例如汇总为 0.70、所有参与汇总的明细均为 0.10，
不能因为汇总超过阈值就通过。测试应分别变异明细和汇总，并保留一致的正向对照，
检查相关有效性条件或复算测量确实变化。仅测试字段存在、数值范围或模型自己构造的
正向样例不足以证明正确。测试方法保存在可进化 Grounding skill 中，实际脚本和
样例留在 `/acceptance/work/`，验证命令和关系可写入现有工作笔记；不引入统一指标
格式，也不把测试说明当作新的科学事实。

重试、澄清或上下文恢复后，以当前请求、已接纳来源和保留工作为依据。可选的
`/acceptance/WORK_NOTES.md` 是草稿，不是科学证据或解析器源文件。把可复用的样本
生成器、测试辅助代码及候选草稿保存在 `/acceptance/work/`；`/tmp` 会在调用间丢失。
复用前核对当前输入，且不要把辅助代码、笔记或候选草稿列入 `parser_files`。科学检查
和 smoke 输入就绪后及时提交完整最终 JSON，仅写入文件不算提交。Grounding 在工具
调用前可收到截止提醒：进入初始剩余预算的最后 20%，且最多提前五分钟，提示为 Stop
纠错留出时间。提醒无法打断进行中的长模型响应，也不延长截止时间。此 skill 不修改
上下文上限，不新增付费摘要器。

## 不完整的组件对比

对 Profile 定义的组件结果协议，可在
`methodology.yaml.experiments.protocols.<名称>.requirements` 中声明可选条件，
区分“科学覆盖不足”和“有效的负向对比”，例如：

```yaml
inconclusive_if:
  artifact: evaluation_summary
  path: coverage.full_matrix_complete
  equals: false
```

组件通过 `experiment_kind` 选择该协议。指定产物必须已在必需产物清单内，且对应
一个 JSON 文件；点分隔字段必须存在，匹配同时比较标量的类型和值。执行、身份、
产物及 trial 的原有检查仍先执行，条件不会将格式错误或失败的 Process 变成
有效科学结果。本条件适用于组件结果验收，不适用于 deferred 或共同测量解析器。

命中时结果为 INCONCLUSIVE，正式结果不携带可比较指标或逻辑产物引用，发布的
原始输出仍可供分析。分析可以 COMPLETE；同链 ITERATE 仍要求 SUCCESS 或
CLEAN_REFUTATION，选错时使用原有纠正／重试额度。此改动不自动补跑缺少的对比。
已有运行保持其冻结运行时和已准入 Profile。

## 自进化与版本选择

专家通过 `SELF_EVOLVE` 修改自己的技能；管理侧通过 `GRAPH_EVOLVE` 修改自己的副本。
现有 Host 检查路径、frontmatter、所有者、字节预算和必要入口的保留。Git 继续保存
版本历史，由已有 Attempt 记录选择版本。结构合格不等于新方法质量更高或成本更低。

已接纳更新可用于后续请求或周期；已绑定请求保留原版本。操作者继续使用
[USAGE](../../USAGE.zh-CN.md) 中的 `plugin-pin`、`plugin-revert` 和 `plugin-unpin`。
不同角色不会互相覆盖插件。无改动候选是合法结果，API 故障本身不构成修改技能的理由。

私有版本不会自动跨用户传播，也不会由 init 导入。公共改进经过普通源码审阅和多任务
验证后进入新版，供新建插件使用。初始 Grounding 通常只运行一次，后续进化不能改善
已经结束的那次调用。新运行直接选择某个私有版本，不在本次实现范围内。

## 预期收益与验证

预期减少重复调查、重复生成通用校验代码和不必要的历史积累，改善阶段交接。必要的
科学工作、供应商延迟和训练时间仍然存在。加载 skill 也有指令成本，因此不保证固定
加速比例。

在相同任务、模型和预算条件下，先比较科学正确性与已接纳结果，再比较已有的总耗时、
token、工具调用和校正记录。适用时由任务实现记录阶段耗时。精确重复读取统计不能覆盖全部 Bash
读取；未知 CLI 价格不代表可核实账单。实际覆盖与限制见[资格验证](../qualification.zh-CN.md)，
实现依据见[设计方案](../design/research-workflow-skill.zh-CN.md)。

## 长实验前的验证与科学筛选

DESIGN 阶段用有明确耗时边界的 CPU 检查验证解析、配置、路径和小规模代码行为，
该阶段没有 GPU 授权。GPU 模型的设备冒烟应写在实际实验入口开头，再由 EXECUTION
通过 Host 提交，在分配到的设备上先检查新增分支，失败即结束该进程。通过后仍执行
完整试验与测量要求，冒烟输出与科研测量分开。不要在设计调用里等待慢速 CPU 训练
或反复轮询。既有工具钩子会在临近截止时提醒保留草稿、测试及待验证事项，并为最终
输出校正留出时间；提醒不会自动延长预算或证明检查已经完成。

使用小规模但有意义的案例，走通实际实现与评估代码，包括适用的产物保存和加载。
训练任务可采用极小训练→保存→加载→评估流程；求解器、数据流水线使用自身的
对应步骤。检查相关设备、维度、单位及边界。GPU 检查仍通过 Host 提交和调度。
在已有工作记录中说明实际检查和未覆盖部分；未变更且仍适用的检查可以复用。
技术失败后先验证对应修复，再重复完整实验。这是任务专属的 agent 工作指导，
不新增统一的验收门槛。

LOCAL 判据应回答假设的筛选问题。改进主张需要适当对照或说明绝对阈值的理由；
零阈值对于增益、误差等完全合理，原始分数为正也不等于优于基线。保留各项目标
及已接受的测量定义，更改判据应创建新假设或修订假设。消融后继续完整评估时，
说明新实验消除什么不确定性。框架不代替专家选择科研路线，也不硬编码数据集阈值。

## 缩短实验周转

后续迭代从保留实现和已接受分析开始，复用可用的数据加载、解析器和仍适用的检查，
在已有工作记录中交接准确入口、选定方案与剩余执行事项。长实验接纳后使用原有
Host handoff 释放 Agent 名额，独立的已接受研究链各自准备下一项实验。

冻结 LOCAL 测量前，在方法允许时选择小规模但有区分力的对照；完整 GOAL 评估仍
保留全部已接受种子、方案、数据集与检查。只有来源、数据/划分、种子、协议和必要
产物匹配，且现有提交规则允许访问时才能复用基线，不把不完整 trial 拼成完整主张。
普通实验日志应报告计划 trial 数及适量的阶段、trial 耗时，先定位低 GPU 利用率的
原因，再调整科研设置或资源并行。这些是 Agent 工作方式的改进，不保证固定加速比。

## 当前实验的估时与性能分析

高开销计算按需读取研究 skill 的性能参考文档，由任务选择有意义的进度单位。
优先复用日志，必要时在任务自身代码中增加及时刷新的阶段、进度、耗时信息和估时计算。
初始化、预热、稳定执行、评估及产物检查分别计时。当前设计的小规模实测用于提交前
预算，当前实验进度用于剩余时间估计；未知收敛或搜索工作量保持未知。估时不会自动
延长已接纳的超时，也不会减少共同目标要求的实验覆盖。

GPU 诊断在设备支持时记录整卡功率及功率上限（mW）、温度（℃）和 SM 时钟（MHz），
沿用已有利用率及显存观测；不支持的字段缺省。整卡读数不能直接代表某个 Process 的
能耗或效率。先根据阶段吞吐和数据等待定位瓶颈，再做有界对照；PyTorch 专用指导
仅在适用时加载。资源授权、科学设置和提交后的 Host 交接流程保持不变。

性能分支也覆盖计算实现：先区分疑似热点与实测开销，再对一项局部改动做有界比较。
PyTorch 指导包括独立循环批量化、成对损失归约、减少不必要的同步和有条件的编译，
以及原有数据加载优化。复用任务测试比较修改前后的输出、适用梯度／更新及数值边界；
同时比较正常执行的端到端耗时、峰值显存和稳定吞吐，将启动开销计入收益。
没有证实收益时可以保持原实现，GPU 利用率更高本身不代表改进。排队与设备授权仍由
Host 管理，专家不能改写或附加分析器到已运行实验；新版种子指导不替换保留的插件或绑定。

已有报告保存工作负载条件、原始证据和预估／实际耗时。`SELF_EVOLVE`／`GRAPH_EVOLVE`
可以改进本专家插件中的方法及参考文档，接纳后供后续请求选择，已绑定版本保持原样。
数值经验必须带适用条件，不自动传播到其他运行或用户。

## 专家技能库

点击专家卡片上的 **技能库**，或全局概览的 **专家技能库**，进入同一个技能工作台。
可以按专家、研究阶段、整个运行或末尾 1／6／24 小时筛选。已结束运行以最后记录的
Agent 活动作为时间窗口终点。阶段筛选用于调用统计和任务结果；进化历史按专家和时间筛选。

页面展示已观察到的原生 Skill 调用、加载成功／失败／未返回、调用分布和可点击的
时间趋势。技能可用、提示词提及、请求绑定、读取参考文件均不算一次 Skill 调用。
加载成功也不证明遵循了方法或改善了结果。重复工具记录和恢复会话的历史重放会排除。
日志缺失、截断或尚未结束时，次数为观察下界；没有时间戳的调用不纳入时间窗口和图表。
首次读取有界并使用缓存，后续刷新可能补齐覆盖。记录不依赖浏览器是否打开，已删除的
日志不能补造。

进化历史区分已接纳变更、完成但未修改、失败和进行中，列出涉及的技能及文件，包括
参考文档和辅助脚本，并分别显示版本接纳、后续请求绑定及后续观察到的调用。技能详情
提供正文、参考文件、整个技能目录的差异和调用记录。并发请求可能使用不同版本。
**效果 / 跟踪** 按实际绑定的 Git 版本、研究阶段、组件和模型展示首次校验通过率、
节点交付率、重试率，以及已报告或预留的重试费用和耗时。每项比率保留分子、分母、
未知和排除数量。“绑定版本的任务结果”和“观测到某技能调用的节点结果”分别展示；
多个技能可能共享节点和成本，不能相加。有效的科学负结果不计为执行失败。

失败链接可打开原始 Attempt；保留了接纳关系时，还能回溯到源假设提案。
每次技能目录变更会持续对照后续版本中阶段、组件和已知模型相同的记录。
相同诊断文本再次出现会标记复发；文本不同也可能属于同一问题。没有后续样本时显示
“待验证”，未观测到复发也不代表修复已证实，更不构成技能质量的因果评分。
筛选会排除不完整的重试链，有界视图和缺失日志均明确标注。

新运行会向提案、CYCLE_REPORT 和 SELF_EVOLVE 节点提供有界的本专家失败与版本反馈，
包含尚未产出实验的设计失败。专家在现有报告和进化摘要中保留目标问题、来源引用、
预期变化与未解决的跟踪事项。触发时机、轮次和预算沿用现有规则，不额外调度进化，
也不根据评分自动选版或回退。若要恢复单个技能，可通过 SELF_EVOLVE 新建私有提交，
恢复该技能完整目录并保留其他技能；整插件 pin/revert 的作用范围不变。

所有视图复用现有日志、Attempt 和 Git 历史，只读展示，不新增第二套持久化技能库，
也不会就地升级已有研究任务。

实现细节见[设计方案](../design/experiment-methods-and-skill-observation.md)。

## 解析器输入与设计时限（2026-10-12）

adapter 83 将 `parser_argv` 中指向已声明原始文件或其父目录的相对参数解析到
`/raw`，解析器源文件参数解析到 `/input`；显式绝对路径保持原义。解析器仍在
`/parsed` 启动，只能读取已声明的只读输入，并在该目录写结果。解析器代码内部
应从 `HYPOLOOM_MEASUREMENT_RAW_ROOT` 定位数据。用普通断言验证已知正负样例的
预期数值；数据缺失或无效必须明确报错，不能变成数值哨兵。结构 smoke 通过不代表
任意科学语义已得到验证。

实验主进程和子进程都应直接从 `HYPOLOOM_TARGET_ROOT` 导入补丁后的代码，不要
用仅映射参考数据的 `HYPOLOOM_READ_ROOT_MAP` 转换该代码根目录。检查修改模块的
实际导入路径。DESIGN 的既有截止提醒提前到最后 20%、最多十分钟；Grounding 仍为
五分钟。优先交付小而可运行的改动，复用已有检查，把设备 smoke 放在已授权 Process
开头。时限和 GPU 权限均不扩大。冻结解析器修正仍需修订假设／新周期，旧运行保留
原有 bundle。
