# 上下文、记忆与恢复

[English](context-management.md) · 简体中文

新建 ACI-24 运行在短模型会话之间保留专家身份、Git 工作区、已接受结果和记忆。
普通节点的每次调用都建立新会话，包括设计、执行、分析、图管理和重试。
原生压缩是可选优化，不增加必须成功的付费摘要调用。三轮 Debate 保留现有有限
分叉协议；容量失败时明确结束该辅助任务，不重放已超大的会话。

## 输入和记忆

当前请求提供准确的任务身份、约束和来源引用。总内联预算选择较小的当前输入；
完整冻结原文仍位于提示列出的 `/inputs` 路径。行动前必须读完适用的 Goal 约束和
实验规范，包括已文件化的内容。`R1` 等别名和编号路径只属于当前请求，换会话或
原生压缩后必须以当前映射为准。

已有节点摘要、轮次报告、专家记忆、研究视图和论文材料支持按 ID、路径和关键词
检索。摘要保留决策理由、有条件的负结果、未解决错误和下一步意图，不能改写事实
或授予权限。只有 CYCLE_REPORT 写入 MEMORY.md。不增加向量库或第二套科研事实。

基础设施重试保持冻结输入逐字不变。有限运行观察说明前次 Attempt 和已提交实验，
不作为可引用的科学证据。未接受代码留在私有工作区供检查和测试；未写下的推理
无法保证恢复。晋级方案的代码继续传给后续研究链，会话重建不会丢弃这一代码来源。

## 容量配置

提示构建和现有 relay 共用容量策略，检查包含工具定义、结果和思考块的完整请求，
不重写签名思考块或工具消息对。有效上限取已知部署、runtime、框架工作上限的
最小值，再扣除输出、工具增长及估算余量。

缺省工作上限是 **262,144 个估算 token**，采用保守 UTF-8 字节量估算；总内联
输入最多 **49,152 字节**。这是应用层工作额度，不是探测到的供应商窗口，也不是
通用 tokenizer 保证。重试将内联额度减半，最多减至四分之一，原文仍可按需读取。
必要材料过大时可能明确容量失败，不能省略约束来通过。

新运行可在 `methodology.yaml` 的 `memory` 下配置：

| 字段 | 含义 |
|---|---|
| `working_context_tokens` | 框架工作上限，默认 262144。 |
| `context_window_tokens` | 已确认的实际部署窗口；未知时省略。 |
| `runtime_context_tokens` | 已确认的 runtime 上限；未知时省略。 |
| `max_inline_input_bytes` | 总内联输入额度，默认 49152。 |
| `input_usage_semantics` | `separate_cache` 表示 Anthropic 兼容接口的 input/cache 分列；input 已含缓存时选 `includes_cache`；无法确认时选 `unknown`，不显示无依据的输入总量。 |

限额必须为正整数。已知窗口更小时应显式配置；模型名 `[1m]` 后缀和调用累计
token 预算不能证明物理容量。计数端点不可用不会取消本地检查。配置在创建运行时
冻结，切换 API 连接不会修改容量配置或迁移运行。

Web/TUI 分开显示末次输入及来源、框架工作上限和累计用量。provider 用量区分最终
值与部分观察，transcript 观察单独标注。显示工作额度不代表供应商窗口已知；缓存
命中的输入仍占上下文。

Web 同时显示 provider 末次实测输入与 UTF-8 字节估算，后者用于本地准入；两者
可能明显不同。输出预留、工具预留和估算余量单独显示。只有 CLI 明确报告
`compacting` 才显示正在压缩，不能从输入下降推断。原生 `compact_boundary`
事件提供已完成次数、前后输入量和耗时；未提供的字段显示未知。

调用记录中的 `context_observation` 统计成功的原生 Read，以及同一冻结输入、
同一起始行和行数的重复读取。不同范围、可变代码文件和 Bash 内部读取不计入
这一重复数，故它是保守观测，不代表所有冗余。实时读取有界尾部，截断时显示
`partial`；缺少记录显示 `unavailable`，不能解释为零。`input_material` 显示
来源字节、唯一内容字节、重复内容字节及文件化数量；这些不是 tokenizer 计费量。
逻辑节点中的材料统计是各次提示统计之和，“唯一内容”不表示跨调用全局去重。

逻辑节点、专家和运行的 `context_recovery` 从既有计费记录汇总首次上下文失败
及其后恢复调用的费用、token 和调用耗时，成功恢复也计入；两组互不重复。
预留与未知费用不冒充已付费用。命令详情保留缓存用量和材料统计，专家卡显示
恢复费用下界及费用未知次数。跨调用读取计数只在同一逻辑节点内比较冻结 ref，
不根据文件名推测跨节点版本。这里的恢复费用不等于优化带来的节约。
金额沿用 runtime/CLI 报告值，不代表已核对供应商账单。CLI 不认识模型计价时，
仍可能按回退费率给出美元估算；此时优先比较请求、token 和缓存分布，不能据此
声称实际扣费减少。一次调用未正常结算时，其预留上限也不是实际消费。
Web/TUI 和支持包显示 CLI 原生会话的未知计价标记；没有标记证据时单独显示
不可用，不把它当作已验证价格。该标记不会改写已经记录的金额或预算。

## 恢复与停止

容量重建使用 `methodology.yaml` 的 `budget.max_infrastructure_retries`。
设为 **0** 就不会自动重建；`max_retries` 控制模型输出纠正，是另一项额度。
提高后者不能启用前者。重建仍受调用费用、运行总预算和停止条件约束。

| 状态 | 行为 |
|---|---|
| 本地容量不足、明确输入过长、原生摘要失败 | 关闭并计费当前调用，捕获代码、归档，再在原有基础设施重试和总预算内重建。 |
| 最低内联量下首请求仍被本地容量检查拒绝，且所有生成请求均未转发 | 结束无效重试，说明需要在新运行调整输入或 runtime 工作额度。缺少完整诊断时不启用此提前停止；已有工具进展的超限仍可重建。 |
| HTTP 200、零输出、`max_tokens` | 记录输出异常；仅在窗口已配置且输入接近边界时推断容量原因，正常非零输出截断单独处理。 |
| API 认证、限流、额度不足 | 进入已有[API 恢复](provider-recovery.zh-CN.md)，已提交实验继续。 |
| 恢复额度用尽 | 显示节点和原因；API 重试不能重新打开最终失败节点，也不能绕过必要验收。 |

新调用提交前先查询自己的实验。重放已提交命令保留原身份，换会话不产生第二个
实验、不清零费用。归档失败仍沿用既有严格终结处理。分析技术失败本身不再取消
合法的下一轮修订，裁决、更新、报告、预算和终止控制仍决定能否前进。API 错误
不是科学否定。执行控制调用超时耗尽后，若其拥有的实验已闭合并产生有效结果，
已接受分析仍可在预算内要求下一次实验；归档失败或尚未完成的实验不满足这一条件。
旧运行保留原 bundle，不支持跨版本迁移。

## 测量与引用

`DELTA_FROM_BASELINE` 的 parser 输入 `value=0.72`、`baseline=0.68`，框架得到
`0.04`。parser 已返回期望差值时使用 `VALUE`；相对差值还要除以基线绝对值。
原生本地 parser 诊断显示中间值，请用非零基线自测。框架不按负号猜测科学含义。

原生 Stop 将 web_sources 与实际交付的检索结果、同节点先前的有效检索证据比对，
复用 Host 终检验证器。论文包或历史文字中的 URL 不代表实际 Web 检索。错误提前
反馈，仍受当前调用的纠正次数和时间预算约束；Host 最终验收继续保留。
