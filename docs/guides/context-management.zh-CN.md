# 上下文、记忆与恢复

[English](context-management.md) · 简体中文

ACI 28 的启动预检、节点级 GPU 故障恢复及上下文/进度观测见[运行恢复指南](runtime-recovery.zh-CN.md)。

新建 ACI-25 运行在有界模型会话之间保留专家身份、Git 工作区、已接受结果和记忆。
新任务和容量重建使用新会话；同一冻结任务的普通纠错、传输重试，在归档完整且
已有容量观察留有续作余量时，可以恢复原会话。缺少证据时使用新会话。
ACI-24 旧运行仍保留每次 Attempt 都重建的原行为。
原生压缩是可选优化，不增加必须成功的付费摘要调用。新建 ACI-29 辩论每轮使用
新会话，显式携带原专家已接纳来源、相关事实及上一轮双方的已接纳观点；重试也
使用新会话，仍受现有次数和预算限制。裁判读取六条输出，胜者接续绑定实际第三轮
和原专家来源。ACI 14–28 保留原生会话分叉及原失败行为。
新会话在最小输入下仍不能通过本地容量检查时，会明确要求调整输入；单纯增加
重试次数不能解决该问题。

## 输入和记忆

当前请求提供准确的任务身份、约束和来源引用。总内联预算选择较小的当前输入；
完整冻结原文仍位于提示列出的 `/inputs` 路径。行动前必须读完适用的 Goal 约束和
实验规范，包括已文件化的内容。`R1` 等别名和编号路径只属于当前请求，换会话或
原生压缩后必须以当前映射为准。

已有节点摘要、轮次报告、专家记忆、研究视图和论文材料支持按 ID、路径和关键词
检索。摘要保留决策理由、有条件的负结果、未解决错误和下一步意图，不能改写事实
或授予权限。只有 CYCLE_REPORT 写入 MEMORY.md。不增加向量库或第二套科研事实。

基础设施重试保持冻结输入逐字不变。有限运行观察说明前次 Attempt 和已提交实验，
不作为可引用的科学证据。未接受代码留在私有工作区供检查和测试；未写下的推理
无法保证恢复。晋级方案的代码继续传给后续研究链，会话重建不会丢弃这一代码来源。
ACI-25 的续作观察包含有限工具参数、路径、读取范围、检查和错误，不再只有末三条
结果。Grounding 可以发现保留的 `/acceptance` 草稿，并继续读取同任务之前已授权的
论文材料。可选的 `/acceptance/WORK_NOTES.md` 用于记录接口、检查和未完成事项，
不是已接受的验收源码；不要把它列入 `parser_files`。普通节点仍不能写专家 MEMORY.md。

## 容量配置

提示构建和现有 relay 共用容量策略，检查包含工具定义、结果和思考块的完整请求，
不重写签名思考块或工具消息对。有效上限取已知部署、runtime、框架工作上限的
最小值，再扣除输出、工具增长及估算余量。

缺省工作上限仍是 **262,144 token**，总内联输入最多 **49,152 字节**。
这是应用层工作额度，不是探测到的供应商窗口。ACI-25 不再因为重试编号增加就
自动缩小内联量，容量计算依次使用：

1. 已经观察到、与当前输入对应的供应商计数结果。框架不会额外发计数请求。
2. 同一次 relay 中，完整成功请求的实测 usage，加上经过核对的新增文本字节估算
   和既有预留；已测且未变的历史不再整段按字节当 token 计算。
3. 无可用计数时明确标注 UTF-8 字节估算。此时拒绝表示“无法确认容量允许”，
   不等于供应商报告了真实溢出。

这些估算不是通用 tokenizer 保证。历史改写、模型/协议或工具定义变化使锚点失效；
新增多模态输入、未知缓存语义不能静默沿用。计量识别 CLI 单一 text 块与相同字符串的等价表示，
以及 text/tool_result 块上已知 ephemeral 缓存标记的移动；内容、顺序、工具身份
和签名思考块仍精确比较，不改写请求。锚点仅存在于当前调用；恢复旧会话后，
首请求无法可靠计量时，仍可能需要新会话重建。若上一请求已经超过新 relay 的
字节准入额度，重试直接重建，不再先恢复这段对话；代码、已发布归档和有界恢复
信息仍然保留。单轮生成的大量思考内容仍按新增字节保守估算，因此可能在供应商
报告溢出之前被本地拒绝。重建会消耗既有基础设施重试额度，
额度为 0 时明确停止。独立字节、请求次数、时间、累计 token 和费用上限继续保留；
不能省略必要约束来通过容量检查。

新运行可在 `methodology.yaml` 的 `memory` 下配置：

| 字段 | 含义 |
|---|---|
| `working_context_tokens` | 框架工作上限，默认 262144。 |
| `context_window_tokens` | 已确认的实际部署窗口；未知时省略。 |
| `runtime_context_tokens` | 已确认的 runtime 上限；未知时省略。 |
| `max_inline_input_bytes` | 总内联输入额度，默认 49152。 |
| `input_usage_semantics` | `separate_cache` 表示 Anthropic 兼容接口的 input/cache 分列；input 已含缓存时选 `includes_cache`；无法确认时选 `unknown`，不显示无依据的输入总量。 |

限额必须为正整数。已知窗口更小时应显式配置；模型名 `[1m]` 后缀和调用累计
token 预算不能证明物理容量。计数端点不可用不会取消本地检查。配置在创建运行时
冻结，切换 API 连接不会修改容量配置或迁移运行。

若兼容服务使用`mimo-v2.6-pro[1m]`等自定义模型名，stderr可能出现
`[claude-code:unrecognized_model]`。Hypoloom会把选定模型原样传给Claude Code，
保留`[1m]`；该提示本身不能证明请求失败，也不能证明实际窗口为1M。
结合provider结果、usage及调用失败码判断，不为消除提示自动删后缀或更换冻结模型。

Web/TUI 分开显示当前请求估算、最近成功请求实测及各自的 exchange 编号、框架
工作上限和累计用量。当前拒绝请求不会借用前次 usage 填满占用条。provider 用量区分最终
值与部分观察，transcript 观察单独标注。显示工作额度不代表供应商窗口已知；缓存
命中的输入仍占上下文。

部分提供商在流式响应开始时先报零输入，结束时才返回真实输入及缓存用量。
未完成响应中的临时零值显示为“待返回或不可用”，上次完整实测和当前估计
分别保留；这不表示 Agent 没有上下文。非零流式输入和有效的最终用量仍按
实测显示，此规则不改变计费或容量上限。
胶囊中的“上次”标识历史实测；当前输入读数尚不可用时，不填充当前占用条。

没有模型标识或内容的完整零用量终止流不代表实测输入为零，不替换前一个有效的
容量观测，也不能证明 API 已恢复。调用记账时，仅在逐请求记录和费用精确吻合
的情况下，才使用 CLI 完整模型账本纠正输入／缓存类别混合增减及漏计的压缩输出。
未知或不一致的账目仍拒绝，预算检查继续使用验证后的总量。

Web 明确区分供应商计数、实测历史加增量估算和字节回退。输出预留、工具预留和
估算余量单独显示。ACI-25 在接近可用输入量 80% 时，通过已有原生工具 hook 提示
收束工作、保留简短进展；提示不授予工具权限、不替代输出验收、不强制发摘要请求，
也不能保证模型一定遵循。只有 CLI 明确报告
`compacting` 才显示正在压缩，不能从输入下降推断。原生 `compact_boundary`
事件提供已完成次数、前后输入量和耗时；未提供的字段显示未知。

调用记录中的 `context_observation` 统计成功的原生 Read，以及同一冻结输入、
同一起始行和行数的重复读取。不同范围、可变代码文件和 Bash 内部读取不计入
这一重复数，故它是保守观测，不代表所有冗余。实时读取有界尾部，截断时显示
`partial`；缺少记录显示 `unavailable`，不能解释为零。`input_material` 显示
来源字节、唯一内容字节、重复内容字节及文件化数量；这些不是 tokenizer 计费量。
逻辑节点中的材料统计是各次提示统计之和，“唯一内容”不表示跨调用全局去重。

逻辑节点、专家和运行的 `context_recovery` 从既有记录区分首次上下文失败与后续
恢复调用，成功恢复也计入，两组互不重复。Web/TUI 统一以 **token** 展示用量：
已报告、预留、尚未结算的观测下界与不可用记录分别显示；专家卡与重试详情展示
跨周期恢复 token 和用量未知次数，未知不等于零。不再把美元估算及未知定价提示
作为 Web/TUI 用量指标。历史计费记录和用户明确配置的金额预算控制仍保留；这些
观测本身不能证明节约或科研质量改善。命令详情保留缓存与材料统计，跨调用重复
读取只在同一逻辑节点内比较冻结 ref，不根据文件名推测跨节点版本。

## 恢复与停止

容量重建使用 `methodology.yaml` 的 `budget.max_infrastructure_retries`。
设为 **0** 就不会自动重建；`max_retries` 控制模型输出纠正，是另一项额度。
提高后者不能启用前者。重建仍受调用费用、运行总预算和停止条件约束。

| 状态 | 行为 |
|---|---|
| 本地容量不足、明确输入过长、原生摘要失败 | 关闭并计费当前调用，捕获代码、归档，再在原有基础设施重试和总预算内重建。 |
| ACI-25 全新会话首请求被本地拒绝，完整记录证明所有生成请求均未转发 | 结束不改变输入的无效重试，说明需要在新运行调整输入或 runtime 工作额度。恢复旧会话、缺少完整诊断或已有工具进展时仍保留有界重建；ACI-24 沿用最低内联量规则。 |
| HTTP 200、零输出、`max_tokens` | 记录输出异常；仅在窗口已配置且输入接近边界时推断容量原因，正常非零输出截断单独处理。 |
| API 认证、限流、额度不足或上游服务暂时故障 | 进入已有[API 恢复](provider-recovery.zh-CN.md)，已提交实验继续。 |
| 恢复额度用尽 | 显示节点和原因；API 重试不能重新打开最终失败节点，也不能绕过必要验收。 |

新调用提交前先查询自己的实验。重放已提交命令保留原身份，换会话不产生第二个
实验、不清零费用。归档失败仍沿用既有严格终结处理。分析技术失败本身不再取消
合法的下一轮修订，裁决、更新、报告、预算和终止控制仍决定能否前进。API 错误
不是科学否定。执行控制调用超时耗尽后，若其拥有的实验已闭合并产生有效结果，
已接受分析仍可在预算内要求下一次实验；归档失败或尚未完成的实验不满足这一条件。
旧运行保留原 bundle，不支持跨版本迁移。
操作者重载或切换 API 连接后，该运行后续普通重试使用新会话，避免跨部署复用旧对话；
已经 OPEN 的调用仍按其既有绑定归档，不因之后的控制重新解释。

## 测量与引用

`DELTA_FROM_BASELINE` 的 parser 输入 `value=0.72`、`baseline=0.68`，框架得到
`0.04`。parser 已返回期望差值时使用 `VALUE`；相对差值还要除以基线绝对值。
原生本地 parser 诊断显示中间值，请用非零基线自测。框架不按负号猜测科学含义。

原生 Stop 将 web_sources 与实际交付的检索结果、同节点先前的有效检索证据比对，
复用 Host 终检验证器。论文包或历史文字中的 URL 不代表实际 Web 检索。错误提前
反馈，仍受当前调用的纠正次数和时间预算约束；Host 最终验收继续保留。

Grounding 与后续阶段共用的方法见[研究工作流指南](research-workflow.zh-CN.md)。
技能自进化复用现有 Git 插件，不新增另一套记忆存储。
