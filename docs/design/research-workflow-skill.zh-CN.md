复用已有只读插件视图与 Git 绑定，在原生 DESIGN、EXECUTION、RESULT_ANALYSIS
prompt 中直接提供该版本的 `performance.md`，附原有挂载路径与提交号。这是临时
prompt 展示，不是新接纳输入、回执或性能校验器；现有 Git／挂载生命周期和普通

报告，不从最新种子补写。其他阶段与无插件绑定的辅助角色不注入性能正文。
prompt 诊断只记录送达状态与字节数，不将其视为检查完成。

worker 对照、启动与生命周期成本、资源约束，以及随机／模型状态保留。不规定
固定 worker 数或利用率目标，不代替项目选择算法，不减少科学覆盖。

维护范围为一个参考路由、有界 prompt 渲染及普通回归；若原生技能加载以后能按
阶段自动送达精确绑定版本，可移除此展示层。现有冻结运行和私有插件不热修改。
验证区分真实 provider 收到指导、CPU 生命周期闭环与真实模型遵从／GPU 加速，

## Grounding 收尾与可恢复编写（2026-10-08）

只读调查发现，一次调用在 3,000 秒预算后超时，未进入原生 Stop，尽管此前已报告
50/50 本地检查通过并写出最终候选草稿。模型请求区间的并集占调用耗时 98.2%，
其中包含压缩；一次响应耗时 631.7 秒、耗尽 32,000 输出 token，最终产生空参数
Write。另写的 schema 校验脚本重复了 Host 的职责。放在 `/tmp` 的样本生成器和
候选辅助文件在下一次调用中消失，而有界续接摘要把早期探索放在近期成果之前。
这些证据支持优化编写与提交过程，不支持扩大预算或放宽科学标准。

方案复用现有机制与边界：

1. 区分任务自身的原始数据计算、科学边界及有效性变异，与 Host 已测试的比较
   运算符、严格数值相等和 ALL/ANY 归约。有效性变异直接断言目标 check 与其他
   check 的预期，无须让原始样本同时达到所有性能门槛。每项科学条件仍需合格
   样例；低分 smoke 仍只证明接口。保留所有验收规则和校验器。
2. 将现有 `_output_schema` 的值渲染到调用私有目录，只读挂载为
   `/runtime/output-schema.json`。它与 Stop 和 prompt 使用同一值，是随调用清理
   的读取视图，不是第二份格式定义、接纳产物或校验权威。现有私有目录生命周期
   与 bwrap 只读挂载已经足够，不新增摘要、检查点、门禁或校验协议。
3. 在现有 `/acceptance/work/` 保留可复用测试、生成器与候选草稿，按需更新简短
   `WORK_NOTES.md`。只有声明的解析器源文件会被接纳，辅助内容仍是草稿。复用
   遵守当前输入、会话和容量准入。沿用最多 12 条续接观察，优先近期命令、修改、
   最后错误和一个来源起点，再从近期不同操作补齐，避免早期探索挤掉已完成工作。
4. 共同验收器 Grounding 复用 PreToolUse 提醒，在初始剩余预算最后 20%、且最多
   提前五分钟提示收尾。截止时间不变，提醒不消耗纠错次数、不赋予接纳权限。
   容量观测缺失不会隐藏时间提醒；提醒无法打断已经进行中的长模型响应。

科学检查和完整 smoke 就绪后及时提交完整 JSON，按真实 Stop 错误修正。指导采用
完整且适量的源代码编辑，减少一次输出截断损失整段实现。模型、effort、输出上限、
重试次数、会话续接准入和运行中的版本绑定保持不变。未进行有界真实模型对照前，
不宣称具体耗时改善。

验证范围见[资格验证](../qualification.zh-CN.md#grounding-收尾与恢复2026-10-08)。

## 实验供给与显存反馈（2026-10-07）

旧运行的只读样本覆盖 21.2 小时、21 个已提交实验和 7 个单候选批次，平均并行
GPU Process 数为 1.48，设计调用的中位耗时为 36.7 分钟。该并行数不是共享机器
的整卡算力利用率。21 个实验均申报了估计；18 个结束进程中有 17 个虽保留可靠的
归属峰值采样，却因覆盖未知而不展示峰值，后续 Agent 多次沿用偏小的旧申请。
另有三次显存保护中断及两次脚本失败增加周转时间。

方案复用批次读取器，为提案及管理器提供实际接受宽度、最近三个批次和 OPEN 链数。
这些观察仅供决策参考。两侧论证及综合主动寻找上限内可独立检验的机制，保留有效
负结果的信息价值；不强制凑候选、不增加队列、不越过依赖。现有 Host 负责独立链
之间的交错准备和执行。

显存历史展示可靠采样得到的占用下界，完整校准仍使用原有覆盖检查。未知采样不会
因此启用共享或释放初始下限，准入器继续使用原字段及精确工作负载匹配。Agent 可据此
复核过小估计，但不能把相近配置悄悄当成同一负载。“未申报估计历史”的扩展经核对
原始提交后排除，不属于本次运行的故障。

阶段指引强调增量实现、协议兼容的基线复用、精确交接和冻结前的有界 LOCAL 筛选；
GOAL 覆盖保持完整，trial／阶段耗时沿用普通日志。复用原始记录、批次验证、Git
插件版本和测试，不新增保障机制、持久化状态或权限来源，不剖析或修改旧运行进程。
新运行通过既有 bundle 和插件初始化采用改动。脚本化与原生闭合验证证明接口联通，
不代表已测得真实模型的假设质量或 CUDA 吞吐提升。结果见
[验证记录](../qualification.md#experiment-supply-and-memory-feedback-2026-10-07)。

## 1. 问题与目标

MERC-causal-202609281629 的 Grounding 成功完成了原生压缩和一次通过的最终校验。
其中仍有重复目录调查，以及已有 Host 验证器之外另写最终输出 schema 校验脚本的工作。
不能仅凭任务验收器有 726 行，就认定它冗余：科学约束仍需要实际计算和有效测试。
原始分析保留在 `.local/analysis/grounding-review-20260928/`。

引入一个 `research-workflow` skill，跨适用阶段复用证据、定向调查、实现和验证方法。
保留任务自己的科学逻辑、现有专门技能及框架权限。减少可避免的工作，不要求每个节点
都执行完整调查和测试清单，也不根据一次成功运行承诺固定比例的加速。

## 3. 预期工作模式

公共入口引导 Agent 先确定当前义务，使用已提供的上下文、索引和接纳证据，再补齐
未解决的前提，复用适用实现，并进行当前阶段需要的验证。资料缺失、截断或过期时仍须
重新调查；相互独立的读取可以合并，不设置工具调用次数或代码行数目标。

| 阶段 | 使用方式 | 保留的边界 |
|---|---|---|
| Grounding | 核对实际数据/接口，受托时编写和测试共同验收器 | 保持用户目标和已确认回答；仅整理背景的 Grounding 不擅自创建验收器 |
| 文献与假设 | 追溯已有来源，调查相关缺口，提出可区分的假设 | 使用现有阅读/提案方法，不强制编程或生成解析器夹具 |
| 设计与实现 | 读取已接纳接口、复用代码，测试改动及已声明的局部测量 | 共同验收器只读；GOAL-only 任务不擅自新增局部测量 |
| 执行与修复 | 检查实际 Host 状态和必要条件，使用已有提交、替换和交接路径 | 不直接启动 GPU 实验，不绕过归属控制反复轮询 |
| 分析与报告 | 核对原始证据、对比口径及结论限制 | 本地测试和模型叙述不等于已接纳科研结果 |
| 自进化 | 根据证据定位具体不足，小幅修改技能；允许不改 | 沿用现有所有者、预算和版本选择规则 |

运行时用简短指令指定真实绑定的插件名和当前阶段，加载公共入口及相关参考，不一次性
加载全部阶段内容。将重复的建议性方法从 runtime/专门技能中归并；权限、输出接口和
执行约束继续由框架代码维护。不新增“必须调用几次工具”或“必须证明调用 Skill”之类
准入关卡，实际加载和使用通过资格验证检查。

接入方式与实现核对结果：

- 初始 Grounding 通过既有资源绑定增加明确的只读路径。`agent_sessions.py` 保留
  原有管理/Observer 校验，针对初始 Grounding 任务增加精确条件。其已选执行角色、
  模型和预算保持不变，不授予 `/plugin-update`。
- 进一步检查确认 `_cycle_reports_enabled` 是运行版本条件，不是当前 Profile 的轮报
  开关。当前科研阶段关闭图进化后仍保留资源，因此保留原路径并增加回归验证，不新增
  资源结构或科研周期。受限阅读助手、QUERY_PLAN 和没有插件绑定的辅助角色保留
  原有精简指令。

## 4. 验收与跨任务适用性

各任务仍通过现有可执行解析器接口实现自己的科学计算：分类任务可计算 F1，数值优化
可计算目标值与可行性，复现任务可核对声明的协议和结果差异。公共 skill 不包含 ERC
数据集、seed 数量、文件命名或阈值。

最终结构化响应复用 Host Stop 验证及既有 parser smoke 执行。skill 说明这些能力，
避免 Agent 在工作区重写通用 schema 校验器。科学解析器仍需有效的正例、反例和边界
测试：smoke 通过只说明接口可运行，不证明科学语义正确。复用已有科学实现前，仍需
核对其假设和输入语义。解析器输出 measurements/checks，Host 保留目标判定职责。

不强制所有任务采用同一原始证据文件布局，不增加用户必须填写的 DSL。
科学目标存在实质歧义时，继续使用现有人工澄清路径。

## 5. 自进化与共享

所有角色从同一公共方法开始。专家通过 SELF_EVOLVE 修改自己的插件，管理侧通过
现有 GRAPH_EVOLVE 路径修改自己的插件。不增加额外进化 Agent，也不在每次调用后
新增反思回合。使用职责范围内已关闭 Attempt 的证据、已接纳报告和原始失败记录；
不把实时日志年龄或完整 transcript 填入冻结的科研输入。API 故障本身不是技能缺陷。

Host 进行已有结构/归属验证并产生 Git 提交，后续请求或周期按既有规则选择版本。
已绑定请求仍使用原版本；固定与回退沿用 pin/revert/unpin。结构合格不等于推理更好、
成本更低或科研质量提高。更新不能改变已接纳验收标准、阈值、权限或框架校验，也不能
覆盖其他角色的插件。经验可进入已有接纳摘要供其他角色参考，不静默替换对方版本。

初始 Grounding 通常只执行一次，后续进化不能缩短已经发生的调用。公共方法的改进
通过普通源码审阅和多任务回归进入新版，供新运行使用。私有进化版本不自动发布、
跨用户合并或由 init 导入。私有版本直接导入新运行需要另行增加明确的版本选择入口，
作为可选后续工作，不作为首版承诺；旧验收器和旧科研结论不会变成新任务的验收事实。

## 7. 预期收益与限制

预期减少重复探索、模型生成的通用校验代码和不必要的历史长度，改善阶段交接，并让
运行内的方法改进有证据可依。任务事实与科学要求来自当前请求，因此能跨用户适用。

skill 本身会增加少量指令成本，模型也可能不完全遵循。它不能消除必要的科研调查、
供应商延迟、训练时间或任务验收器开发。本次证据支持优化方向，不支持量化收益承诺。
不扩展时间看板、RAG 服务、跨用户自动学习或上下文额度。
