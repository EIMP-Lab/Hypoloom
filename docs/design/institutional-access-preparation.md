# 机构全文集中准备与有界恢复设计

状态：2026-10-01 方案已按 A–D 批次实施，lifecycle v11；最终验证结果见
[验证记录](../qualification.md)。原设计基于 dev `8ec9dd5`。本文承接
[机构全文架构](institutional-literature-access.md)，供后续实施与验收使用。
可用命令与参数以[使用指南](../guides/institutional-access.zh-CN.md)为准。

目标是让研究者在开始前集中准备常用平台的登录，研究期间尽量复用会话；不能访问的
论文有明确结束方式，不让新文献持续制造人工等待。推荐默认行为为：**先获取公开全文，
再使用已有机构会话；后台遇到人工认证就返回缺口，只有用户主动登录才开启有界等待。**
登录成功、取得某篇全文、Agent 实际阅读及科研证据接纳仍是不同事实。

## Windows 专用目录继承权限准备（2026-10-03）

用户的前台 Run 明确返回 browser_profile_must_be_private，目录 ACL 显示一个额外
本地组通过父目录继承了读取权限；当前用户、SYSTEM、Administrators 均有完整权限。
既有校验正确拒绝，但创建目录只继承父目录权限，且 Connect 未提前执行检查，导致
后台以统一退出码 2 结束，用户反复启动无法恢复。问题与学校、论文或研究主题无关。

复用 Windows ACL 和原私有校验：只对当前用户拥有的默认 Institutional-<browser>
目录处理额外继承 Allow。在内存中移除继承规则，再把需要保留的继承授权和 Deny
按原 SID、权限及传播标志加入显式副本；原显式合法规则保持不变。一次写回后用原
校验重新读取确认。自定义目录、显式额外授权、其他
所有者和目录重定向继续拒绝自动修复；不修改父目录、组成员、SSH 或浏览器文件内容。
已有子项沿用 Windows 的 ACL 继承传播，不做递归权限重置。新增目录也走同一流程。

Connect/Init 在任务归属核验后、后台启动前准备该目录，失败直接显示；Run 在确有
连接目标、启动/复用浏览器前准备。前台发现输出初次及转入无目标等待的提示，不逐轮
刷屏；Connect 隐藏任务返回和前台 Run 保持窗口的区别写入程序说明及运行指引。
不放宽原允许列表，不新增持久状态、配置、哈希或第二个权限判定源。验证以实际
PowerShell 编排及 Windows ACL 替身为限；原生 ACL 传播、桌面/SSO 须客户端确认。
Windows 权限操作依据 [Set-Acl 的保留继承规则示例](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/set-acl#example-4-disable-inheritance-and-preserve-inherited-access-rules)。

同日原生回读纠错：`c254d5f` 实际保留了额外授权，仅去掉 `(I)`。此前测试替身
错误地认为 SetAccessRuleProtection(true,true) 会立即清除内存 ACE 的继承标志；
[.NET 实现](https://github.com/dotnet/runtime/blob/v9.0.0/src/libraries/System.Security.AccessControl/src/System/Security/AccessControl/SecurityDescriptor.cs)
只设置保护，而 [RemoveAccessRuleSpecific 的底层实现](https://github.com/dotnet/runtime/blob/v9.0.0/src/libraries/System.Security.AccessControl/src/System/Security/AccessControl/ACL.cs)
跳过继承 ACE。以上一次写回方案取代原两种 API 的错误组合。纠正替身先复现红例，
新增原生 Windows 临时目录回归（Linux 不执行），涵盖子项继承和内容保留。
错误码区分自定义目录、显式额外授权、写入失败及读回不合格。

对旧版已写入的显式残留不能假装它仍是继承规则；只有用户前后 ACL 证据确认的具体
账户可用一次性 `icacls <专用目录> /remove:g <已确认账户>` 恢复。不增加迁移标记，
不自动识别/删除任意显式授权；正常连接器继续拒绝未知显式授权。

- 准备进程的现有状态与单次等待 deadline 直接产生剩余秒数、说明和固定回复选项。
  `instructions` 输出可原样展示的文本，`reply --text` 只接受当前阶段提供的词语，
  平台仍由已有 provider 键约束。工具完成通知、其他阶段的回答和过期回答不能推进。
- 失效的临时控制入口输出明确的重新准备步骤。结束摘要直接生成
  `remaining_preparation_argv`，保留连接参数、模式和未完成样本，只准备剩余平台；
  原 init 原样执行，不迁移旧进程或丢弃原科研启动身份。
- 运行指引要求原样转发代码和选项，禁止临时编造路径、等待期限、后台回答及重入
  命令。程序校验约束实际可执行动作；并不声称能彻底禁止基模生成额外自然语言。

复用原控制 socket、阶段、provider、deadline 和 Windows 任务归属。无新持久配置、
摘要、标记或问答回执。首次 Windows 本地执行、PowerShell 7.2+ 与已有 SSH 认证
仍为前提；学校认证仍在浏览器完成。验证覆盖实际生成脚本的执行、引号/下载失败、
不重入、原 socket 问答、期限不被查询延长及过期清理。

## init 内完成连接和交互（2026-10-02）

最新 init 的 client 准备批次始终处于 waiting_for_client，却按三个平台分别等待
120 秒后超时；科研运行尚未创建。后台命令还依赖终端 input()，缺少标准输入时，
浏览器即使已打开也会抛出 EOFError。该问题与研究主题、出版社账号无关。

本批实现以下完整链路：

1. 准备阶段先使用现有浏览器后端和串行执行器验证连接，使用已有连接超时；
   未连通不进入平台队列，不将连接失败归因为订阅不足，不要求逐平台重试。
2. init 使用显式的对话准备模式。复用临时 PreparationControl 私有 socket，
   查询进度并提交完成、样本验证、跳过、仅公开或结束操作；后台进程不读 stdin。
   输出立即刷新。用户等待有有限期限，结束/超时释放原连接资源和临时目录。
   独立终端模式保持兼容，EOF 返回可理解的结果并清理，不冒充登录完成。
3. Windows 连接脚本增加统一 Init 入口，复用同一 SSH 目标和仓库位置，自动推导
   标准 Python/state 路径、运行连接发现并进入服务端 /autoresearch init。
   不要求另开终端启动助手或手工编辑助手配置。连接进程覆盖后续研究使用期，
   仍只给活跃运行分配隧道；无活跃运行不启动浏览器。既有 Run/Install 入口兼容。
   首次取得本机入口和有效 SSH 认证仍是实际前置条件，服务器纯 SSH 会话不能
   启动一台没有本地执行通道的电脑。已有入口在 init 中报告实际连通情况。
4. bootstrap 输出完整的对话准备命令；运行指引先查询连接，只有观察到页面打开
   才告知用户登录。所有平台结果及偏好仍复用现有 preparation_summary，并回到
   原启动身份审阅。不创建研究 run、改写 Profile、保存账号密码或迁移旧运行。

失败边界是 init、客户端进程和后台交互之间的衔接，原有控制 socket、操作进程、
浏览器身份和平台结果足以表达状态。临时问答通过现有私有传输传递，不增加数据库、
摘要、持久就绪标记或第二套认证事实。客户端任务继续沿用原有系统任务归属校验。
回归覆盖连接前无平台操作、单次有界失败、后台问答与 EOF、取消/超时清理、样本
真实性和预览只读；原生浏览器/SSH 在隔离环境验证，Windows 可见桌面须如实标注
实际可验证范围。

## init 中明确选择机构访问（2026-10-02）

本次方案：复用 `bootstrap inspect` 的 `missing`、生效配置与参数数组，不增加配置文件、
询问回执或第二份运行状态。已确认的缺口是：机构模式没有进入缺失项，交互助手可能
略过；inspect 还使用旧手动 `plan`，会拒绝 client，或给 local/server 注入不兼容的
固定端点。原有 launch 预览测试未覆盖完整 inspect → launch 路径。

1. 同一参数 `--institutional-browser-mode` 增加 `off`。未传表示尚未选择；off 明确
   关闭自动机构浏览器；local/client/server/existing 保留原义。CLI 枚举和交互选项
   来自同一份定义，不默认替用户选择。关闭不影响公开检索和 OA 回退；机构面板导入须保留启用模式。

3. inspect 与 launch 复用同一个机构配置预览及原校验器。off 不构建浏览器／队列，

## init 自动准备浏览器连接（2026-10-02）

本节保留最初发布的连接启动设计。随后实施的
[运行级自动端口与清理](#运行级自动端口与清理2026-10-02)已替代自动研究连接的常驻
行为、同机 CDP 和 Host 前连接准备方式；显式手动旧连接仍保留其原所有权边界。
当前命令与行为以该后续章节和使用指南为准。

用户补充：必须覆盖项目运行在带图形界面的原生 Linux 机器上的情况。自动准备应按
浏览器所在位置及当前可用会话选择路径，不能把 Windows 加反向隧道作为唯一模式。
下表中的启动器与 init 协调已实施；可见桌面、Windows 系统任务及容器部署的真人验收
独立记录，不以无头测试代替。实现接口见[使用指南](../guides/institutional-access.zh-CN.md)。

| 场景 | 浏览器与连接的准备方式 | init 的职责 |
| --- | --- | --- |
| 原生 Linux 桌面，同机研究 | 在当前用户可用的图形会话中启动或复用专用可见 Chrome/Chromium，直连本机回环 CDP；无需 SSH 隧道或 Docker | 检查桌面会话与浏览器，执行已选择的准备动作，再验证 CDP 可用性 |
| Linux 服务器＋另一台电脑的浏览器 | 浏览器所在电脑的项目脚本维护浏览器与 SSH 反向转发；客户端也可以是 Linux | 复用已连通端点；断线时提供客户端启动方式；不能凭服务器 init 启动未配置控制通道的另一台电脑 |
| 无可用桌面的服务器，浏览器常驻服务器 | 沿用现有专用浏览器容器及受限远程桌面入口，无需跨机 9222 反向转发 | 检查或启动所选服务；保留部署失败和人工登录提示，不静默切换部署方式 |

普通 inspect／预览继续只读。用户选定“准备机构访问”后才启动浏览器或连接；此选择
可包含启动策略的审阅，不需要每个专家、每篇论文重复确认。准备失败仍允许明确选择
公开全文继续研究，不将浏览器启动或学校登录设为所有研究的必经步骤。

原生 Linux 桌面的具体约束：

1. 优先采用用户指定或之前选定的浏览器位置／程序／专用配置目录；自动探测只提供建议。
   没有已选路径时，才依据当前环境推荐同机桌面或远程方式，不按操作系统名称硬选。
2. 同时考虑 X11 与 Wayland。DISPLAY、WAYLAND_DISPLAY、XDG_RUNTIME_DIR 等是检查线索，
   不能只凭环境变量存在便宣告窗口可见；启动后还要验证真实 CDP 连接，并让用户能看到
   登录窗口。通过 SSH、sudo 或服务启动的 init 不自动借用另一用户的桌面权限。
3. 使用当前用户拥有、跨新运行复用的专用浏览器目录；不因每次 init/run 新建目录而丢失
   登录，也不拿日常浏览器的默认目录开启调试。首次选定位置须明确，后续保持一致。
4. 先检查所选端点是否已经可用，再决定启动。端口占用、配置目录被占用、程序缺失和
   图形会话不可用分别报告；不终止未知进程、不删除浏览器锁、不自动下载替换浏览器。
5. CDP 只绑定回环地址，浏览器保留正常沙箱。测试用的 headless、no-sandbox 或
   password-store=basic 参数不能自动进入真人登录配置。窗口和登录仍由用户控制。
6. 浏览器会话可跨多个新运行复用；单个 Host 结束仅清理其所属页面并断开连接，不关闭
   用户浏览器或清除配置目录。需要独立停止入口时，只操作明确由该启动器管理的资源。

三种连接方式准备完成后，都进入现有同一流程：CDP 连接检查 → 出版社集中准备 →
样本全文验证 → 将已审阅端点交给新 Host。浏览器连通、样本可读、全平台订阅和
未来会话有效性仍是不同事实；SSO/MFA 过期不能由启动器自动解决。

实现应继续复用启动配置、现有 CDP 校验、浏览器配置目录／自身锁和适用的系统进程
管理能力；不新增 Cookie 库、浏览器注册表、连接凭据数据库或另一套运行权威记录。
若需要常驻，Windows 任务计划与 Linux 用户会话的启动机制各自适配，保持同一组
准备／状态／停止语义，而不是为不同平台复制文献下载与认证判断。

验收须区分真实桌面与无头回归：本机 X11／Wayland 可见启动和重入、已有端点复用、
同目录并发启动、端口冲突、SSH 中缺少桌面权限、手动关闭浏览器后的下一次准备、
跨运行会话复用及连接中断后的公开回退。没有真实桌面的验证环境不能宣称该部分通过。
之前的 Windows／Springer 订阅结果也不能替代 Linux 原生桌面的真人验收。

依据：[Chromium 用户数据目录与实例限制](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/user_data_dir.md)、
[X11／Wayland 平台支持](https://chromium.googlesource.com/chromium/src/+/main/docs/ozone_overview.md)、
[Chrome 调试端口与独立目录](https://developer.chrome.com/blog/remote-debugging-port)。

  安装及适用的只读兼容检查。当前开发环境没有图形会话；隔离便携 PowerShell 可测试
  语法、参数和子进程管理，但不能验证 Windows 系统 API。真人 Linux
  桌面、Windows 登录任务以及机构样本需独立标明验证范围，不用无头测试冒充。

不新增 PID 文件、连接注册表、凭据库、hash 或身份回执。Linux systemd 单元、Windows
任务计划、Docker 服务元数据和浏览器自身目录锁已足以表示配置与进程归属。停止操作
复核这些现有来源，只操作所选管理对象；外部端点可复用，但不会被声明为本项目创建。
未知端口或目录占用不给予自动停止权。读取连接状态不代表已验证论文访问权限。

## 运行级自动端口与清理（2026-10-02）

状态：已实现，完成自动化与隔离原生验证；[结果及真人验收边界](../qualification.zh-CN.md#运行级机构连接与清理2026-10-02)。
自动分配的机构访问端口和隧道属于
**单次运行**，每次运行结束或终止后释放；登录配置目录继续按用户保留。不得用
“浏览器可以常驻”代替运行端点的释放，也不得因清理端口删除 Cookie、已接纳论文
或研究归档。本节取代上节自动启动部分的常驻生命周期；手动旧连接命令保留兼容。

复用 TUI/Web 的原则：由实际监听者绑定端口 0，再读取分配结果；显式正整数保持
固定端口和可见冲突。不先探测空闲端口再释放重绑，不新增全局端口分配表、PID 文件
或运行结束标记。连接配置以现有运行 ID、所属用户、系统服务归属及真实监听为依据。
现有运行状态决定是否终结，系统服务与实际进程决定资源是否仍存活，分别核验。

| 生命周期事件 | 要求 |
| --- | --- |
| init 预览 | 不分配端口，不建立隧道，不创建浏览器 |
| 正式启动 | 为本次运行建立独立连接端点；读取实际端口、核验归属和 CDP，再交给该 Host 使用 |
| 连接已准备但启动失败／取消 | 回收本次启动创建的监听、转发和受管辅助进程；CREATE_RUN 结果不明时先沿用现有状态核对，不能误停已成功运行 |
| 暂停研究、等待人工、关闭 TUI／Web 观察端 | 不视为运行结束，不释放仍服务于该运行的连接 |
| COMPLETED／FAILED／CANCELLED | 在既有终态处理路径释放该运行的监听与隧道；不能只依赖整个 Host 退出，Host 可能承载其他运行 |
| 显式停止 Host、SIGTERM／Ctrl+C | 走现有收尾路径，清理其持有的运行连接；停止 Host 不伪造研究终态 |
| Host 崩溃／被强制结束 | 本进程监听随进程退出释放；受管子进程通过现有系统服务归属收尾，不仅依赖 Python finally；远端转发在 SSH 连接关闭或存活检测超时后释放 |
| 同版本 Host 恢复 | 先重新核验运行状态与旧资源；终态运行不得重建连接，未结束运行才恢复其连接；清理旧资源不能干扰新的 Host 实例 |

故障清理有明确时限；网络分区不能承诺远端端口瞬时释放。验收必须实际观察监听关闭、
隧道进程退出和端口可再次绑定，不能仅以函数返回成功或进程管理命令已提交作为完成。
两个运行并发时，结束 A 只释放 A 的端点，B 的连接与论文获取必须继续可用。

端口是临时传输地址。Host 恢复或隧道重连时优先恢复仍属于本运行的原端点；地址确需
改变时，消费者必须取得并校验新地址后才恢复使用，不能让旧 Host 继续访问已被别人
占用的端口。实现需遵守现有配置钉住规则：新版本区分可变传输地址与审阅过的连接策略，
不得为换端口修改保留运行的冻结配置、弱化版本检查或迁移旧运行。

平台资源的边界：

- Windows 客户端为每次运行建立独立服务器转发；运行终结后自动重连不得将它重新
  建立。登录启动任务只能提供客户端连接能力，不能无运行也永久占用研究端口。
  Windows 自有浏览器及其登录目录仍属用户，结束服务器运行不授权关闭外部浏览器。
- 原生 Linux 的自动受管浏览器随本次使用结束正常关闭、保存登录目录并释放其端口。
  若允许多个运行复用同一浏览器，须有各自独立运行端点，使用既有系统服务归属协调
  共享资源；最后一个使用者结束才关闭底层受管浏览器。不得直接让多个 Chromium
  实例同时打开同一个配置目录，也不以复制登录凭据实现并行。
- 自动管理的服务器容器按用户隔离配置目录／卷与服务归属，运行级映射随使用结束
  释放。停止一个运行不能关闭其他运行仍使用的容器，保留登录卷。
- 显式 existing 端点由外部管理者拥有。项目只清理自身创建的运行连接，不终止未知
  监听器或外部浏览器；不能把外部监听仍在存活报告为本项目已关闭。

独立集中登录仍可在无研究运行时使用，其临时连接属于 prepare 操作并在操作结束时
清理，保留登录目录。它不制造虚假运行，也不持有未来运行的端口。自动端口分配只
解决争用；跨用户访问权限仍须验证，不把动态端口、run_id 或回环绑定当作认证凭据。

实施选择及必要访问保护：原生 Linux 使用 Playwright 已有的独立持久浏览器上下文与
进程管道，不额外开放 CDP TCP；同一目录已占用时明确拒绝，允许各运行选择不同目录。
Windows 反向转发落在当前 Host 提供的用户私有 Unix socket 路径，而非无认证的服务器
TCP 后门。需要 CDP TCP 的消费者使用运行进程持有的临时回环监听与内存 bearer；沿用
Web observer 的访问令牌语义，令牌不进入运行配置、公开状态、日志或凭据文件。

这项访问保护的依据是：(1) 共享服务器中另一账号能连接回环 TCP，错误连接会暴露
机构登录浏览器；多用户隔离已由用户明确纳入范围；(2) 失败资产是运行所属的 CDP
访问通道，边界是服务器 OS 用户之间；(3) Git、运行主键、事务、文件权限及普通测试
不能认证 TCP 对端，文件权限只用于私有 Unix socket 和控制入口；(4) 最小补充是复用
既有内存 bearer 模式保护实际 CDP 监听并关闭无认证后端入口，维护成本为 HTTP／
WebSocket 握手与退出回归；若浏览器客户端可直接使用受权限保护的本地传输，可移除
这层 TCP 适配。它不是新的事实登记或研究状态权威。

实际实施补充：连接随既有 Host 中的活跃 run 建立，终态在同次 tick 收尾，未连接
浏览器继续沿用原有有限获取和回退规则。local 使用持久上下文管道；client 的临时
socket 目录、server 容器使用用户级 systemd 中的 EOF 服务，进程被强制结束也触发
收尾。临时 GUI 凭据只经用户私有控制接口显式读取。容器启动脚本会删除 Chromium
锁，因此在现有配置目录上持有 flock，并在重启前检查 Docker 已有的 Mounts，防止
上次守护进程退出到容器删除之间再次打开同一目录。不新建锁文件或配置登记表。

真实 SSH 重连复现断开后的残留 socket 路径；重连前通过原 Host 核验当前 run/path，
只移除同用户、类型正确且 connect 返回拒绝的旧 socket。真实监听不接管。此处理
复用 OS inode 和 socket 状态，不创建完成标记。真实浏览器继承 CDP 身份校验。
恢复创建新路径和内存令牌，端口由实际监听者分配；固定端口冲突清理本次部分分配，
只使对应运行连接暂不可用，不终止 Host 或其他运行。资源释放后沿用原有有界获取重试。
原有获取期限不缩短，原生浏览器在已执行操作的有限期限结束后正常保存并关闭。

最小验收包括两个运行同时分配且互不影响、正常完成／取消／启动失败清理、Host
强制退出与同版本恢复、隧道断线期间终结后不再重连、旧端口被占用后的安全拒绝，
以及下一次新运行使用保留浏览器目录。仅用隔离运行和端口验证，不操作现有科研运行
或用户当前登录隧道；Windows 与可见 Linux 桌面继续单独记录真人验证范围。

初始化增加可选的“准备机构全文”步骤，也提供独立的本地命令入口，便于没有运行时先准备。
该入口不创建研究 Host、run、Attempt 或科研归档，不调用模型。命令形状建议为
`python -m hypoloom institutional prepare`，复用现有浏览器连接参数；该接口
现已实现。初始化的普通预览仍只读，只有用户选择准备动作才打开浏览器页面。

1. 连接专用浏览器并展示位置：支持原生 Linux 桌面、已有客户端连接及显式服务器模式。
2. 从已有受支持平台目录选择常用平台。选择表示准备登录，不改变研究的检索范围。
3. 顺序打开所选平台的公开机构入口，由用户在浏览器完成 SSO/MFA。
4. 用户可提供该平台一篇有权限的规范论文链接或 DOI，点击“验证样本全文”。验证复用
   现有字节、大小、PDF 内容身份检查；临时内容用后释放，不发表为研究证据。
5. 展示“样本全文已验证及时间”“需要人工操作”“样本不可访问”或“未检查”，然后继续

平台目录复用 `PROVIDERS`，避免界面和适配器各维护一份名单。公开平台首页仅用于人工
准备，由专用准备操作允许；不能放宽学术文献 URL 准入，使首页变成论文。SAML 元数据
地址仍不能作为交互入口，认证跳转和临时签名 URL 不进入保存的配置。

“验证样本”只证明该篇当时可读，不展示“全平台有权限”或“永久已登录”。新进程重新
连接后，浏览器可以仍有会话，但界面中的旧验证结果不作为授权依据。准备过程仍由
同一个浏览器 worker 串行执行；不创建第二个认证服务。每平台至多一个待执行准备动作，

运行中 TUI/Web 同样展示完整平台目录，空论文列表也能打开平台准备页。Web 沿用独立的
文献操作授权和同源检查；只读链接仍只能查看。研究开始前使用本地准备入口，运行后通过
Host 操作入口管理同一浏览器，避免两个管理界面同时修改工具所属的登录标签。

## 会话与平台使用偏好

Cookie 与浏览器 storage 继续只由专用浏览器管理。关闭一个 Host 不清除登录，后续
Host 连接同一个浏览器可复用有效会话。浏览器重启能否复用取决于站点保存方式和会话
有效性；换电脑、换配置目录或学校使会话失效都可能要求重新登录。

平台只提供两种明确的使用偏好：

| 偏好 | 自动获取行为 | 人工操作 |
| --- | --- | --- |
| 使用现有机构会话 `auto` | 公开途径失败后尝试已登录浏览器；需要认证时停止本次后台等待 | 可主动登录、检查或导入 PDF |
| 仅公开途径 `public_only` | 保留公开检索、开放全文备选及已接纳来源复用，不自动打开机构页面 | 可导入 PDF；“启用并登录”明确改回 auto |

启用机构功能时默认所有已支持平台为 `auto`；集中准备只优先打开用户选中的平台。
全局不配置浏览器时维持原有公开检索。初始偏好和期限进入现有 Host 启动配置与
bootstrap 最终审阅，例如新增可重复的 `--institutional-provider-mode IEEE=auto`，
以及数值期限参数。这些参数已由 CLI 与 bootstrap 共用校验。未知平台、重复冲突值、
负数、无限值或超界期限在启动前由现有参数校验拒绝。

跨新运行沿用偏好使用已审阅的启动参数；不另建全局偏好文件，也不把浏览器会话放进
科研 Profile。运行中修改采用下节的运行级控制，不能直接改写冻结配置。

## 跳过与恢复的范围及持久性

| 操作 | 范围与后果 | 恢复方式 |
| --- | --- | --- |
| 跳过此篇 | 当前运行该规范文献的未完成自动获取，不删除已接纳原文或历史引用 | 恢复此篇，再发起获取；合法 PDF 导入仍可用 |
| 平台仅公开途径 | 当前运行同平台所有专家的后续机构请求；公开检索继续 | 改回 auto，可同时选择主动登录 |
| 打开登录或检查 | 显式开启该平台一次限时人工窗口，不改变其他平台偏好 | 完成后重试受影响请求；超时后可再手动开启 |
| 全文获取超时 | 结束本次请求并释放额度，不作无权限或无文献结论 | 手动重试新建一次有界获取 |

单篇跳过用现有 `bibliographic_identity`（已知 DOI 时）或规范请求 URL 定位。
只在已有材料能证实同一身份时关联 DOI 与落地页；不凭标题猜测，也不创建新的文献别名库。
没有可证实的 DOI 时，界面明确显示“跳过此链接”。跳过可跨该运行的专家生效，不能影响
其他运行的来源权限；来源接纳和归档仍保持原来的专家范围。

需要持久保存的只有用户的跳过、恢复和平台偏好。将这些动作接入现有 `LITERATURE_ACCESS`
控制入口，复用 `store.execute_command` 和 `workflow_commands/workflow_transitions`，
以当前运行的普通自转移记录操作；按既有工作流版本规则加入受支持的控制命令。
同版本 Host 重启后从这些记录恢复覆盖项，数据库结构保持不变。

相同 `request_id` 重投复用既有主键和请求比较；改变操作内容不能借同一 ID 覆盖。
TUI/Web 对这类操作提交当前 revision，冲突后刷新。客户端重试保留原 request_id，
不在每次 HTTP 转发时另造 ID。先完成事务，再让队列采用新偏好；事务成功后崩溃可从
既有命令重建。冻结初始配置加按序控制覆盖得到唯一有效配置，不反写原配置。

打开浏览器、当前排队、样本验证结果和人工等待窗口仍是临时状态。重启不自动重放
登录动作，不重新开启十分钟人工窗口；只重新探测已有会话。自动观察到的无权限、
认证需求或网络故障不写成永久订阅结论。停止中和终态运行保持原操作限制。

## 后台获取和人工等待期限

以下为已实现的首版默认值及已覆盖的期限边界，不是性能承诺：

| 路径 | 默认期限 | 到期结果 |
| --- | --- | --- |
| 自动机构获取 | 入队起 120 秒，包含排队和机构侧重试 | 返回 unavailable，区分排队超时与获取超时 |
| 主动登录或验证码处理 | 点击起 600 秒，每平台一个窗口 | 结束自动观察，提示可再次主动检查 |
| 已检测到需要人工认证的后台请求 | 立即结束本次等待 | 返回 unavailable 和人工操作提示，继续其他来源 |

120 秒只约束机构获取阶段，公开检索继续使用既有 HTTP、PDF 和批次预算。建议两个
期限分别允许 30–600 秒和 60–1800 秒配置，不能配置无限等待。网络状态来回变化、
自动重试、其他专家加入同平台或反复调用同一 URL，都不能刷新原期限。

人工窗口期间每个平台只保留一个认证中的标签，后续同平台请求可复用该窗口，但不能
延长它；其他平台继续调度。人工关闭窗口或窗口到期后，相关等待请求结束，平台进入
“需要主动检查”的临时状态。后台不反复打开登录页，也不以新论文重新制造人工窗口。
用户在浏览器外部完成登录后，可点击平台“检查并重试”恢复；不通过读取 Cookie 判断
认证是否完成。未主动打开窗口的后台认证需求也按平台汇总，仅提示一次状态变化。

主动打开登录时，可将当时同平台因认证未完成的条目作为一组重新排队，期限取本次
人工窗口的结束时间；用户已跳过的论文不自动恢复。窗口中新出现的后台论文仍取
“自身 120 秒期限”和“窗口结束时间”的较早值，不能借别人的登录窗口无限延长。
登录成功只推进仍有效的请求；已超时条目可由用户一次选中后重试，不后台补写旧结果。
这些合并发生在当前 Host；本方案不增加跨 Host 的浏览器协调服务。

浏览器不可用或暂时网络错误仍可在剩余期限内按原退避检查；连接级故障复用现有连接
观测，避免同一断开的浏览器对每篇论文重复连接。明确无权限、身份冲突和无法解析等
结果继续结束该次请求，不自动禁用整个平台，也不把未完成登录标为无权限。

实现应在既有 Acquisition 中保留单调时钟期限，调度和结果收集都检查剩余时间；单次
导航、下载、解析使用原上限与剩余时间的较小值。Host 不等待浏览器线程，Playwright
仍只在原 worker 内使用。当前网络调用按其已有可取消或有界接口退出；逻辑期限到达
后即拒绝迟到结果，不声称 Python 线程可以被强制安全终止。

跳过、模式变更、停止或新一轮人工重试后，旧在途结果不能重新变成 available。
复用现有请求对象身份检查；重试替换原 Acquisition 对象，不增加 epoch、摘要或回执。
到期条目不再占活动待办，释放大字节缓存；保留有界终态描述供工具读取，在容量压力下
按现有终态淘汰方式让出请求名额，避免刚超时就因轮询重新排队。跳过意图由控制记录
保留，不能因缓存淘汰而复活；自动故障观测仍不变成永久禁用。
浏览器继续使用单 worker，并按到期时间、下一次可检查时间和已等待顺序调度；人工
动作有机会执行，但不能让同一平台持续挤占其他平台。

## 统一全文获取与替代来源

| 顺序 | 行为与限制 |
| --- | --- |
| 1 | 执行原来源安全拒绝检查，复用已授权且实际接纳的原文 |
| 2 | 读取公开全文；已知 DOI 时复用当前配置的开放全文定位器与现有下载校验 |
| 3 | 未找到可读全文且平台允许时，尝试浏览器中的有效机构会话 |
| 4 | 认证、权限或期限不能满足时返回明确缺口；Agent 继续其他来源，用户可主动登录或导入 |

单篇显式跳过结束该篇新的自动获取；`public_only` 只省略第 3 步。
已有来源安全拒绝始终优先，跳过恢复、登录、缓存或 PDF 导入都不能清除这个拒绝。
公开全文不因出版社机构路径被停用而被隐藏。禁用机构路径也不删除先前已合法接纳的文献。

正式文献包保留现有检索与备选定位；动态 `web_fetch(mode="document")` 补齐同一 DOI
定位路径。优先从既有定位器抽取按 DOI 调用的部分，由原 `locate(SearchPaper)` 委托，
不伪造查询候选、也不并发调用会改写整个批次诊断的 `retrieve()`。继续复用网络来源
验证、PDF 工作槽、HTTP／时间预算与限流退避。已在该文献包尝试过的定位不因进入
浏览器队列再跑一遍；从现有下载诊断判断。相同请求的结果复用原有有界缓存。

没有可靠 DOI 时，不从相似标题猜一个；向 Agent 提供已知题名和缺口，按已允许的
学术检索工具选择其他来源。换一篇论文属于新的证据选择，不能冒充原论文、转移其
引用或降低既有检索覆盖要求。机构不可用也不能变成 OpenAlex 服务故障、合成失败
QUERY_PLAN 或复制模型费用。所有模型检索仍受原调用、轮次和运行预算约束。

开放仓储中的作者稿或预印本保留实际来源与版本说明，不能因为 DOI 对应就声称获得了
出版社定稿。身份不能确认时保留缺口，不为增加命中率放宽已有 PDF 身份验证。

工具沿用 available/pending/unavailable 的结果语义，返回固定原因及下一步提示。
pending 只用于有明确期限的自动获取或已主动开启的人工窗口；Agent 不应为等登录
反复调用工具。available 后仍须由实际工具读取、PaperWorkspace 接纳和原发布验证器
完成证据交付。完成后的总结、报告和科研结论不会被后台下载改写。

## 界面和配置的呈现

平台行显示使用偏好、最近一次样本或获取结果、待处理数量和剩余人工等待时间，提供
“打开登录”“验证样本”“检查并重试”“仅公开途径／启用机构访问”。论文行提供
“跳过／恢复”“导入 PDF”。这些是文献获取操作，不能混入暂停专家、结束运行等操作。

文案区分“未检查”“需要登录，本次先跳过”“该样本无权限”“用户选择仅公开途径”
和“获取超时”。不以单一红绿灯表示永久权限，不把某篇样本的成功推广到整个平台。
TUI、Web、bootstrap 和指南共用平台名称与状态说明；更新当前仍假设固定 Chrome
安装路径的内嵌连接指引，与已支持 Edge 的指南保持一致。

沿用已有本地文献事件日志记录规范 URL 和固定原因。凭据、SSO 回调、签名参数、论文
正文和 PDF 私有路径不进入状态面板或日志；不增加新的对外消息渠道。启动审阅同时显示
浏览器位于 Windows 还是服务器、连接参数、平台偏好和期限。Windows 模式继续要求
浏览器与隧道在线，准备登录不能消除这项依赖。

## 复用现有事实来源的理由

已复现的失败资产是临时文献队列和人工等待生命周期：无期限等待占额度；临时请求
不能承载跨专家、跨重启的人工跳过意图。浏览器才是认证状态的持有者，控制命令才是
人工偏好的持有者，已发布原文才是科研引用的来源；三者不能互相替代。

本方案用现有队列的期限与普通回归处理前一问题，用现有 SQLite 命令主键、事务和
工作流记录处理后一问题。Git 与既有运行版本管理配置／实现兼容，类型校验和原发布
验证器负责输入／文献接纳。**这些现有机制足够，不需要新防御机制或第二份权威存储。**
因此不增加认证数据库、Cookie 库、订阅权利表、新 SQL 表、私有偏好文件、hash、冻结
合同、检查点或并行回执。新控制使用已有记录结构，运行版本按原规则演进；原安全与
授权边界保持。自动观测的临时状态只能影响当前调度，不能成为永久授权或科研事实。

## 实施批次与验收

| 批次 | 修改范围 | 必须可观察的结果 |
| --- | --- | --- |
| A | 队列期限、后台认证结束等待、迟到结果丢弃和容量回收 | 登录无人处理也能结束请求；其他平台有进展；无无限占额 |
| B | 运行级跳过／恢复／平台偏好、启动参数、既有控制记录及界面 | 重复提交无重复效果；同版本重启恢复人工选择；旧冻结配置不被修改 |
| C | 独立集中准备入口、完整平台目录、初始化与 TUI/Web 集成 | 无运行、无待办也能登录；样本不进入研究证据；只读链接不能操作 |
| D | 动态文献工具复用开放全文定位、研究提示、双语使用文档 | 停用机构访问仍可取得同 DOI 公开全文；取不到时明确报告缺口 |

每批先做有界的故障复现与回归。最终冻结候选后按[现有 G0–G5](../qualification.md#promotion-rules)
执行全量离线／安装验证与适用的只读兼容审计；不把全量套件当作日常调试循环。
真实 Host、broker、Agent 工具、Process、归档、恢复和下一动作构成最终工程闭环。
新鲜隔离 CPU 场景应覆盖多个专家持续发现论文、一次登录复用、无权限与超时并存、
运行级控制重启、停止期间在途结果、报告保留缺口，以及随后实际实验与结果接纳。
独立统计控制效果、工具返回、归档原文、Agent／Process 终态及所属标签／进程残留；
不在测试 oracle 中另写状态归约器。

控制动作与配置按既有工作流／运行时版本规则发布，版本号在实施时按实际改动确定。
旧 Host 不支持的新动作应明确拒绝，不回退成其他操作；新观察端继续保持对旧运行的
只读兼容，不向其注入控制，也不通过修改旧冻结配置开启新功能。

重点反例包括：32 个等待项后新增请求；八个标签容量；两个专家请求同 DOI／不同
落地链接；跳过后迟到成功；重试后旧 worker 成功；人工窗口中新论文不延长期限；
平台仅公开仍命中 OA；一篇无权限但同平台另一篇有权限；403 不能直接推断无订阅；
身份冲突不能被新回退绕过；Host 重启保留人工选择但不伪造登录；已经完成的报告不被
随后获取改写。时间推进使用注入时钟，另有真实浏览器与 Host 的有界退出验证。

真人验收优先在现有 IEEE 会话上增加另一篇有权限的论文，验证跨论文复用；若机构条件
允许，再验证一个其他平台及真实无权限样本。只有样本身份和权限已知才解释结果。
真实浏览器重启及服务器常驻模式单独记录，不能由合成 Cookie 测试替代。当前服务器
Docker 代理问题属于部署前置项，不在此设计中自动改共享代理。

实施验证不产生付费调用。真人登录按实际需要协作；新增付费
兼容 canary 需明确模型、资源及费用上限，不能沿用无关历史额度。GPU 调度未改变，
不为本功能单独增加 GPU 实验或长期 soak；若实施扩大到相关边界，再按既有规则选择
对应验证。当前 118 项测试只证明已发布版本，不算作本提案的实现验收。
