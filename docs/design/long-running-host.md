# 周级运行的 Host 调度与观察开销

状态：2026-11-13 实施与验证完成。用户授权设计、实施、验证和 dev/main 提交推送；
已有研究根、冻结 bundle 和资源池不在本次运行变更范围。

## 复现与边界

持续运行中的控制响应与状态新鲜度分离：72 秒采样的 STATUS 返回中位数
0.092 秒，刷新间隔中位数约 7.3 秒，36 次中 14 次过时。工具日志存在
155 条开始处理前已过期的记录；工具只等 29 秒，主循环只在开头处理队列。
历史执行恢复冷/热缓存分别约 5.65/1.77 秒，每次重建 175 个请求并解码
25,076 次嵌入文件。935 条尝试的 JSON 约 1.25 GiB。

只读审计的 180 秒性能截样中，GPU 重叠检查占 170 秒；每个进程重复构造
全运行学习上下文。单个 SQLite 读取事务内复用该上下文，84 次请求只构造
一次，完整重叠检查约 8.2 秒。前者启用 profiler，后者没有，不能据此报告
精确加速倍率。原进程栈受 ptrace 限制，不能逐一归因既往延迟尖峰。

失败边界是单写 Host 的服务机会、只读历史解析以及进程内暂存对象的生命周期。
数据库、主键、事务和现有验证器继续提供事实与判断；索引只改变访问路径。
不增加节点状态表、审计结论账本或完成标记。Git/事务不能隔离 Python CPU
竞争，所以昂贵的派生读取使用可回收的子进程；原有 Host 仍独占正式发布与写入。

## 实施

1. Oracle 在一次只读事务中检查，按 run 复用 GPU 学习上下文，所有原检查保留。
   周期审计及 Host 投影/角色视图在短生命周期子进程中计算，避免争用 Host 的
   GIL，并在完成后释放解析峰值内存。取消/超时清理该工作进程组，错误仍显示为
   未完成/失败，不能当作通过。临时派生目录沿用现有创建、发布与清理规则。
2. 新数据库增加历史访问索引。执行恢复先用索引筛选未完成且未最终失败的节点，
   仅为候选节点加载最新请求，继续使用原完整请求、重试、handoff 和资源验证。
   已完成历史不再每轮触发嵌入文件解码；没有迁移现有非空研究数据库的路径。
3. Host 在无事务的阶段边界分片工作；每个片段前处理工具，片段间回到现有控制
   循环及状态发布。待办恢复和组件遍历保持轮转，时间预算不依赖是否成功派发。
   单个原子验证/事务不能抢占，因此 250 ms 是让出机会的目标，不是硬实时承诺。
4. 现有只读缓存采用条目和估算字节双上限、LRU 淘汰；超大结果不保留。提交与
   回滚失效、调用者副本隔离保持不变。缓存不成为状态来源，重启从普通记录恢复。
5. 供应商历史事件在逐点呈现时，丢弃已经被原重试归约器永久排除的记录；恢复
   与人工清除仍按原开始时间规则判定，较晚返回的旧调用不能改变恢复结论。
   同一归约器继续计算每一点的状态，避免全成功历史的平方级重复遍历。

这些机制的维护成本是子进程退出/残留、分片取消与恢复、缓存失效和索引等价性
回归。如果未来统一只读服务承接这些任务，可删除进程包装；索引和缓存均可重建。
阶段分片与缓存继续计入既有工作流核心预算：从 lifecycle 的剩余额度转 100 行
给 Host，从 domain 转 50 行给 StateStore。所有原模块和 SQL 仍计入，核心总额
保持 27,550 行；没有通过提取未计数的调度权威绕过此约束。

## 验证计划

- G0：GPU 审计上下文构建次数与真实重叠/损坏拒绝；历史增长、成功/失败/OPEN/
  handoff/重试筛选；队列公平、取消、原子阶段之间的控制机会；缓存预算与隔离；
  子进程取消、超时、冻结源码路径和投影发布所有权。
- G1：冻结候选后完整离线套件、静态检查、公共回归、wheel/安装/新 bundle。
- G2/G3：声明的保留运行只读审计比较，原生 CPU 多轮、故障恢复和独立残留清点。
- 使用合成历史放大及实际只读性能重放验证增长趋势。短期测试不等于周级 soak；
  不将已有 GPU/付费模型验证扩写为本次新证据。

## 已完成的对照

原始 dev `6e1845f` 与候选分别读取同一诊断数据库副本；仅为这个可丢弃副本
创建新索引，没有修改源数据库。该快照没有待恢复执行节点，两版候选集合相同。

| 阶段 | 原始冷／热缓存 | 候选冷／热缓存 |
| --- | --- | --- |
| 执行恢复检查 | 5.646／1.855 秒 | 0.00116／0.000038 秒 |
| 策略快照 | 2.274／0.092 秒 | 2.364／0.092 秒 |

恢复检查阶段的重放进程峰值 RSS 为 1.04／0.12 GiB；候选完成策略读取后的
峰值为 0.16 GiB。这里没有启动 Agent，不是活跃 Host 整体延迟或 RSS 的对照。
1／100／1000 条完成历史加一个待办的回归均只解码该待办请求；500 个交错开始／
完成／恢复／清除点的供应商状态与完整历史归约一致，2000 次成功调用的历史呈现
每次仅向归约器提交一条输入。仍有约 2.3 秒的冷策略读取，不宣称所有历史路径
为常数成本；单次原子工作可能超过调度目标，长期科研记录和制品仍随工作量增长。

十个已终止研究根的只读比较覆盖 8055 个制品，逻辑数据库和制品字节均未变化。
一份报告的问题排列不同，仅对顶层 issues 排序后，十份完整报告均一致；四项
既有交互来源问题和一项既有进程残留问题保留。活跃研究根不作为稳定审计比较。
原比较及排序复核的证据均保留在 `.local/qualification/long-running-host/retained/`。

源码、wheel、独立安装和新冻结 bundle 的 215 个运行时文件一致；安装及 bundle
中的审计子进程实际从各自包内执行，报告与直接审计一致，退出已回收，数据库未改。
完整 G1 加受影响复验覆盖 9109 个身份，8868 通过、241 条件跳过，无遗漏或未解决失败。
21 个原生／CPU 根关闭 571 个 Agent、44 个 Process，313 个登记进程组无残留；
