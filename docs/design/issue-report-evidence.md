# Issue report evidence completeness

The support exporter should preserve enough bounded evidence to explain a long
run's failures, costs and recorded conclusion. Public export remains the default;
research bodies require private opt-in. Exporting never resumes or changes a run,
uploads a package, or turns an observation into workflow authority.

## Reproduced gaps

A retained support case has 63 Attempts. Both public and private exports select
three recent failures and one early failure. The early failure's retries are
missing, obscuring the expensive chain preceding the final budget rejections.
The larger private copy also contains fewer exchange metadata records. Its
inventory cannot explain the unvisited portion. Private names and evidence stay
in their existing ignored locations; regression fixtures use invented data.

Independent reproductions confirm missing first-failure retry descendants,
omitted current budget fields and string USD amounts, silent traversal cutoff,
and an omitted request incorrectly labelled a sanitized input copy. A fixed
512 KiB debug allowance does not grow with the configured package limit.

## Existing sources and bounded projections

1. Expand both recent failures and the first unrecovered failure through existing
   retry links. Keep primary and supporting details distinct. Byte/file/time
   limits still apply; exact-Attempt selection keeps its narrow meaning.
2. Use the existing Agent charge fold and usage projection over all recorded
   Attempts. Preserve observed costs, unknown reservations, cumulative run/role
   limits and remaining amounts separately. Do not label a reservation as paid
   usage or infer which historical threshold bound a call without its evidence.
   Project budget fields from the existing budget definitions, including decimal
   strings; public role identities use the existing disposable alias mechanism.
3. Retain a compact run-wide terminal fact/artifact index. Recent-failure copies
   also select accepted goal/outcome/verdict records and the recorded final-report
   Attempt. Private bodies remain subject to the same sanitization and limits.
   Neither successful Process exit nor a clean Oracle is a scientific verdict.
4. Collect small result/event/exchange/error metadata across selected Attempts
   before large transcripts and provider bodies. Prefer first and last exchanges
   during bounded traversal. Keep the existing time and inspection limits, expose
   them, and inventory unvisited scopes with the limiting reason. A directory
   omission does not claim knowledge of unenumerated file counts.
5. Allocate debug detail space proportionally to the total limit and disclose the
   effective allowance. Preserve compact summaries when dropping large bodies;
   if even summaries do not fit, report that explicitly. Classify input and
   terminal-output fidelity independently. Existing pre-model accounting evidence
   distinguishes an unlaunched Agent from unavailable capture.
6. README and Web preview show selected versus recorded counts, effective limits,
   omissions and actionable ways to obtain more evidence. Scope, private content
   and package size remain independent. Preview/download are fresh observations,
   not a persisted snapshot or a promise of identical bytes on an active run.

No new digest, schema, ledger, checkpoint, receipt, cache or persisted selection
authority is required. The failed boundary is the diagnostic projection/copy,
not the durable run store. Existing primary keys, read-only transactions, typed
budget parsing, sanitization and ordinary regression tests are sufficient.

## Validation and limits

Focused regressions cover a long early retry chain followed by budget failures,
current and legacy budgets, unknown charges, final-report selection, exhausted
time/inspection/byte/file limits, public/private metadata priority, input/output
fidelity, pre-model rejection, credentials and source immutability. Real HTTP and
CLI paths use the same builder. An isolated Host/CPU sample checks actual accepted
facts and final-report export. Freeze the implementation before full offline G1
and package installation checks; retain failures and recheck affected changes.

Previously omitted logs cannot be reconstructed from the supplied ZIPs. This
change improves fresh exports from retained source records, not old archives.
Authoring worktrees, complete datasets and historical live-process state are not
implicitly copied. The collection window bounds attachment traversal, not total
database diagnosis, redaction or ZIP time. Large-run performance beyond these
bounded regression samples remains a measured follow-up, not a latency guarantee.

## Runtime trends (2026-10-07)

The Web **Run trends** button plots experiment/Agent occupancy, total request
RPM, each expert's RPM, Grounding and other run tasks. Ownership reuses
`attempt_scopes`, including reader commissions. The source is existing bound
Attempt intervals and each relay exchange's `upstream_started_at`. The existing
relay already saves that field before waiting for response headers; replay with
the original relay confirms it, so no recording-path change is needed.

No extra collector, table, historical snapshot or parallel counter is needed.
Collection is independent of browser polling and survives observer restarts in
the existing diagnostic files. Historical files without an upstream timestamp
are not assigned an invented one. Missing/unreadable/bounded capture makes the
overlapping RPM buckets unknown; recorded counts remain available as lower
bounds. Diagnostics are best effort, not proof of complete provider-account
activity. Closed pre-spawn attempts do not count as occupied processes. Bound
OPEN intervals are recorded occupancy, not proof of historical OS liveness.

The authenticated, run-bound `/api/trends` reads only on demand. The dialog
refreshes once a minute independently of regular polls, supports time-range and
series selection, pointer/keyboard inspection, both languages and small screens.
At most 1,440 minute-or-coarser buckets cover the entire run; per-bucket peaks
preserve short overlaps. RPM is requests divided by the bucket's duration in
minutes (including retries and partial final buckets), distinct from the live
HUD's sliding 60-second rate. File inspection is bounded to 100,000 entries/five
seconds after database projection; the bound and missing coverage are explicit.

Every run-scoped support export attempts `runtime-trends.json` and
`runtime-trends.csv`, even for one selected Attempt or recent failures. Public
copies reuse the existing role/run aliases and contain no prompts, endpoints or
paths. Both files obey package/file limits; `report.trends` and the inventory
disclose unavailable or omitted data. Startup-only exports have no run history.
No Host or retained state is changed. A current observer can reconstruct old
runs where the existing evidence is present. Reopen the observer to load the new
endpoint and assets.
