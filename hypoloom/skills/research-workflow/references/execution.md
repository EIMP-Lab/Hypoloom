# Execution and repair

Check the design's [performance review](performance.md) before costly submission.
Use the supplied bound text when inlined. Verify its reusable evidence or pending
probe against the actual entrypoint; address missing preparation or explain a
specific limitation through existing repair/handoff paths. Preserve handoff.

Use the Host's current experiment state, returned diagnostics and exact ownership
before deciding whether to submit, replace, wait or hand off. Reuse successful
preparation and inspect the original failure evidence before editing. Distinguish
resource queueing, provider faults, implementation failures and scientific results.

Use the retained entrypoint, implementation notes and completed checks as the
handoff. Recheck changed or unresolved paths, rather than redesigning working
code. After an accepted long-running submission, use the existing Host handoff
to release the Agent slot; do not remain in a polling loop. Preparation of another
accepted independent chain belongs to its own Host task and workspace.

Follow existing resource-planning, experiment-repair and Host tool instructions.
Do not launch GPU experiments directly, create competing schedulers or repeatedly
poll a Host-owned running Process. A waiting handoff is not a scientific outcome.
Repair only the demonstrated cause; preserve accepted measurements and submitted
resource/experiment ownership. Do not repeat an unchanged attempt when its stated
prerequisite is still absent.

Carry the experiment identity, relevant evidence and unresolved next action in
the current node's output. Use existing Host records rather than a second ledger.

For a long experiment, inspect the implementation's small end-to-end check and
whether it covers the selected artifact-loading and evaluator path. If a relevant
integration gap remains, use a small Host-owned experiment to resolve it before
a full run. After technical failure, isolate and test the failing path rather
than repeating all training unchanged. Reuse published artifacts only through
the existing ownership and submission rules; never relabel a failed Process as
a successful experiment. Report any unchecked path in existing notes.

Separate a candidate configuration's observed effect from a claimed mechanism.
When budgets, schedules, data selection or other factors differ across arms,
name those differences and bound the attribution; use controlled follow-up
comparisons when the scientific question requires isolating one mechanism.
Raw measurements from incomplete/failed work are observations, not accepted
scientific outcomes. Missing GOAL acceptance does not imply no raw test data.
